# 金融页 AI 解读研究与实现边界

## 研究对象

本次先检查了以下 GitHub 项目的实际提示词、schema、报告拼装或数据工具代码，而不是只依据项目首页描述：

- `TauricResearch/TradingAgents`：分析师、研究辩论、风险辩论和报告树。
- `AI4Finance-Foundation/FinRobot`：确定性估值模块、分章节报告结构、来源与 AI 内容标记。
- `virattt/ai-financial-agent`：金融工具调用、数据展示组件和基于数据工具的研究顺序。
- `AdvancingTitans/stock-analysis`：证据 bundle、事实/派生事实/分析分层、研究命题 schema、缺失证据和失效条件。
- OpenBB agents 相关实现：工具调用和数据来源返回模式。

## 可借鉴的部分

### 1. 先定义研究范围和数据时点

成熟项目不会把“当前行情”作为没有边界的上下文。报告通常保留标的、市场、适用期间、数据来源、发布时间或取回时间。`TradingAgents` 的工具提示要求以验证后的市场快照作为价格事实来源；`stock-analysis` 进一步把交易日和证据快照放进工作区契约。

本项目因此为金融解读上下文加入：

- 快照取回时间；
- provider、feed、交易时段和缓存状态；
- 当前可见榜单行数与 provider 返回总样本数；
- 市场宽度的上涨、横盘、下跌计数；
- CoinGecko 前 100 样本等覆盖范围说明；
- 缺失基本面、新闻、估值、资金流和未来走势时的明确数据不足说明。

### 2. 事实、派生事实与分析分开

`FinRobot` 的估值和财务计算在模型叙述前完成；`stock-analysis` 明确区分：直接证据支持的事实、依据明确输入计算的派生事实，以及模型给出的分析。这个顺序比把数字和判断混在一段自由文本中更容易复核。

本页当前只把已有的价格、变化、成交额、市值、市场状态和宽度计数作为事实输入。没有新增估值、基本面或预测计算，也不允许模型补齐缺失字段。

### 3. 观点需要证据和反向信号

`TradingAgents` 用 bull/bear/risk 角色强制检查正反两面；`FinRobot` 将风险、催化剂、估值和主要结论拆成独立章节；`stock-analysis` 的 `research-claim` 要求方向、适用期间、证据 ID、缺失证据影响和失效条件。

本项目采用更小的本地只读版本：模型返回正向、负向和中性/分化信号，每条信号必须带有快照中连续复制的证据行。这样既保留反向检查，也避免把不完整的行情快照包装成完整投研报告。

### 4. 结构化输出比自由 Markdown 更适合界面

研究项目在最终报告层普遍有稳定章节或 typed output。自由 Markdown 适合长文，但不利于校验条数、方向、证据和 UI 状态。本项目新增 `financeInterpretation` 动作，固定返回：

```json
{
  "stance": "constructive|mixed|cautious|insufficient",
  "summary": "当前快照的简短总结",
  "signals": [
    {
      "direction": "positive|negative|neutral",
      "text": "事实性观察或谨慎解释",
      "evidence": {"quote": "快照中的连续原文"}
    }
  ],
  "watchItems": [
    {
      "text": "后续观察项",
      "evidence": {"quote": "快照中的连续原文"}
    }
  ]
}
```

服务端 schema 会限制最多 6 条信号和 4 条观察项，并拒绝不能在原始快照中找到的引用。渲染层使用 `textContent` 展示校验后的字段，不直接信任模型返回的 HTML 或 Markdown。

## 不采用的部分

- 不复制 TradingAgents 的自动交易提案、仓位、止损或 BUY/HOLD/SELL 结论。
- 不复制依赖联网搜索、新闻抓取、SEC 文件或用户未选择资料的 agent 工作流。
- 不把 FinRobot 的估值、预测或同业数据接入当前没有对应 provider 权限的场景。
- 不把公开网页、研究库或开源客户端当成已获得市场数据展示和再分发授权。
- 不把模型的“信心”显示成量化正确率，也不把“偏强/偏弱”解释为投资建议。

## 本项目的交互契约

1. 用户主动点击“AI 解读”才发起请求，行情加载和后台刷新不会自动调用模型。
2. 请求只携带当前内存中的一份行情快照，不自动附加工作区、图片、音频、API Key 或其他资料。
3. `sourceRevision` 同时绑定总览和榜单取回时间；行情更新后，旧解读继续显示但明确标记为历史快照，提示用户重新生成。
4. 再次生成时保留上一份完整解读；生成失败、取消或超时时仍回退显示上一份内容，只有新的结构化结果校验成功后才原子替换。
5. 结果只描述当前快照的市场语气、正负信号、分化信号和后续观察项，不预测价格，不给出买卖或仓位建议。
6. UI 同时保留 provider、feed、事件时间、取回时间、缓存和覆盖范围等数据边界。
7. 上一份解读只保存在当前窗口内，不会写入 LocalStorage、工作区导出或金融快照缓存，应用重启后不会恢复。

## 仍然存在的限制

证据引用只能验证模型是否引用了输入中的文字，不能证明模型的解释一定正确。因此这项功能仍是辅助阅读，不是独立研究结论。榜单覆盖、数据延迟、provider 权限、样本偏差和不同市场不可比等问题，仍必须以页面上的数据边界为准。未来如加入历史 bars、基本面或新闻，应为每类数据定义独立的来源、时间边界和缺失状态，再扩展结构化 schema，而不是继续扩大一段自由文本。
