# Requirements

## Product Version

**Launcher MVP v0.1：本地统一搜索与可扩展命令入口**

本版本目标是建立可用的启动器闭环：快捷键唤出 → 搜索 → 键盘选中 → 执行动作，同时提供本地扩展的安装和运行基础。在线商店、云同步和复杂扩展页面不属于 MVP。

## Problem Statement

Dynamic Panel 已经保存了待办、笔记、链接和常用指令，但这些内容分散在不同 Tab。用户从其他应用开始工作时，需要先展开面板、寻找页面、再点击内容。现有全局快捷键只能打开工作台，不能直接定位目标或执行命令。

用户还需要一种可控方式把个人脚本和服务接入工作流。如果直接把脚本塞进 renderer 或主进程，会破坏 Electron 安全边界或影响整个应用稳定性。

## Goals

- G-001：任意应用中通过配置的全局快捷键进入启动器。
- G-002：在一个结果流中搜索当前支持的本地来源。
- G-003：完整支持键盘导航和明确的主动作/次动作。
- G-004：支持收藏、别名、最近使用和可解释排序。
- G-005：为本地扩展提供可验证、可超时、可卸载的最小运行协议。
- G-006：保持现有工作区数据格式和平台安全约束。

## Non-Goals

- NG-001：首版不提供在线商店、账号、云同步或自动更新。
- NG-002：首版不提供全盘实时文件索引；可以先支持应用和已保存工作区资源。
- NG-003：首版不允许扩展直接渲染任意 HTML/网页 UI。
- NG-004：首版不把旧“常用指令”文本变成可执行 shell 命令。
- NG-005：首版不承诺阻止已安装本地扩展使用其自身获得的操作系统权限。
- NG-006：首版不复制 Raycast 的 AI、复杂表单、多页导航和团队功能。

## Personas

### P-001：工作区用户

每天在学习、创作、开发和生活任务间切换，希望快速打开笔记、链接、项目和待办。

### P-002：快捷操作用户

有固定的网页、文件夹、复制文本或脚本入口，希望使用别名和快捷键减少重复操作。

### P-003：本地扩展作者

能够编写 JavaScript/TypeScript，希望以 manifest 声明命令，并通过标准输入输出响应搜索和执行请求。

## User Stories

- US-001：作为用户，我按启动器快捷键后可以立即在搜索框输入文字。
- US-002：作为用户，我输入笔记标题、链接名称或待办内容的一部分，可以看到匹配结果并按 Enter 打开对应页面。
- US-003：作为用户，我输入应用名称，可以启动本机应用；启动器随后关闭并恢复原来的工作上下文。
- US-004：作为用户，我可以将结果收藏或设置别名，空搜索和精确别名搜索会优先显示它。
- US-005：作为用户，我按 `Cmd/Ctrl+K` 可以看到当前结果支持的动作，并用键盘执行。
- US-006：作为用户，我可以在设置中安装本地扩展，查看其权限，启用/禁用或卸载。
- US-007：作为用户，我搜索扩展命令时，坏扩展或超时扩展不会让启动器卡死。
- US-008：作为扩展作者，我可以用 manifest 声明一个或多个命令，并通过 JSON Lines 返回结果。
- US-009：作为用户，我可以从启动器直接创建待办或笔记，并在执行前看到目标来源。

## Functional Requirements

### 唤出和窗口

- FR-001：系统提供独立的启动器全局快捷键设置，默认候选为 `Alt+Space`；不能覆盖现有工作台快捷键。
- FR-002：快捷键唤出启动器时，窗口显示在鼠标所在屏幕的顶部居中位置，并立即聚焦搜索输入框。
- FR-003：启动器打开时，窗口进入独立 launcher 状态；展开窗口不受 Windows 折叠态 `setShape` 的窄输入区域限制。
- FR-004：Escape 关闭启动器并恢复此前焦点；第二次 Escape 不产生额外操作。
- FR-005：失去焦点默认关闭启动器；正在执行动作或打开动作面板时需避免误关闭。
- FR-006：动画沿用现有动效 token，并支持 `prefers-reduced-motion`。

### 搜索和结果

- FR-007：搜索结果必须包含稳定 `id`、标题、可选副标题、图标、来源、类型和至少一个主动作。
- FR-008：空查询显示收藏和最近使用结果，并按来源分组；无数据时显示可操作空状态。
- FR-009：搜索支持大小写无关的标题、别名、关键词和副标题匹配；精确别名优先于前缀、模糊匹配和最近使用分数。
- FR-010：内置来源首版至少包括本机应用、链接、笔记、待办和旧常用指令；剪贴板作为设置可选来源。
- FR-011：结果列表默认显示有限数量，方向键循环移动焦点；上下键选择，Enter 执行主动作，Tab 或右键进入动作上下文。
- FR-012：查询、选择项和来源筛选不修改原始 LocalStorage 数据；索引从现有数据即时或缓存派生。
- FR-013：搜索输入 URL、绝对路径或应用名时，结果应提供安全的打开动作；链接只允许公开 HTTP/HTTPS，路径由主进程校验。
- FR-014：搜索结果出现变化时保留当前选择的稳定 ID；若被过滤则回退到第一项。

### 动作、收藏和别名

- FR-015：动作面板使用 `Cmd/Ctrl+K` 打开，Escape 返回结果列表；动作至少包括执行、收藏/取消收藏、复制标题/目标和打开所属页面。
- FR-016：用户可以为支持配置的结果设置唯一别名；空别名移除，冲突时显示占用项并拒绝保存。
- FR-017：用户可以收藏/取消收藏结果；收藏和别名随工作区迁移。
- FR-018：每次成功执行记录最近使用时间和次数；失败执行不提升排名。
- FR-019：动作必须声明确认级别；删除、卸载和高风险系统动作需要二次确认。

### 内置动作

- FR-020：应用结果由平台适配器发现，执行通过主进程打开；失败时显示可理解错误。
- FR-021：链接结果复用现有安全打开路径，不允许 renderer 直接调用任意 Electron API。
- FR-022：笔记、待办和链接结果可以跳转到对应 Tab 并选中目标对象；新建动作可以打开对应创建界面。
- FR-023：旧常用指令只提供复制文本动作；用户明确创建扩展命令后才可以执行扩展动作。
- FR-024：系统可提供“计算器”和“快速网页搜索”作为后续内置来源，MVP 可不实现。

### 扩展管理

- FR-025：扩展 manifest 必须声明 `id/name/version/description/author/commands`，命令必须声明 `id/title/description/mode`。
- FR-026：扩展安装支持本地目录；zip 安装可作为同一阶段的可选实现，但必须解压到受控目录并拒绝路径穿越。
- FR-027：安装前显示扩展名称、版本、作者、命令、入口和权限；用户确认后才写入扩展目录。
- FR-028：用户可以启用、禁用、卸载扩展；状态变化立即影响搜索，不需重启。
- FR-029：扩展命令支持 `declarative` 模式和 `process` 模式。declarative 仅由 manifest 提供固定结果；process 通过宿主协议动态返回结果。
- FR-030：动态查询请求至少包含扩展 ID、命令 ID、查询文本、请求 ID和取消信号；响应必须通过 schema 校验。
- FR-031：扩展动作只能调用宿主公开的受限动作，如打开安全 URL、复制文本、打开允许的路径或跳转工作区页面。
- FR-032：扩展进程必须有启动超时、单次查询超时、执行超时、输出大小上限和并发上限；超时后可终止并回收。
- FR-033：扩展崩溃、协议错误和非法结果只影响该扩展，并在设置中提供诊断信息。
- FR-034：扩展数据写入独立的扩展目录或受控 storage API；不得直接写入任意工作区文件。
- FR-035：扩展权限至少区分 `network`、`readFiles`、`writeFiles`、`shell` 和 `clipboard`，默认最小权限；高风险权限在搜索结果和设置中可见。

### 设置和诊断

- FR-036：设置页增加启动器快捷键、来源开关、收藏/别名管理和扩展管理入口。
- FR-037：扩展列表显示启用状态、最近错误、最近运行时间和权限；支持复制诊断信息。
- FR-038：设置变更写入当前工作区或应用设置的明确位置，并兼容 `workspace.json` 迁移。

## Non-Functional Requirements

- NFR-001：启动器打开后搜索框可输入时间目标为 150ms 内，内置来源首屏结果目标为 100ms 内。
- NFR-002：单个扩展查询默认超时 800ms，扩展执行默认超时 5s；具体值可配置但有上限。
- NFR-003：扩展崩溃不得导致主进程、renderer 或现有面板状态崩溃。
- NFR-004：所有输入来自扩展、LocalStorage 或文件的内容都必须 schema 校验和长度限制。
- NFR-005：启动器支持 macOS 13+ Apple Silicon、Windows 10/11 x64；平台差异封装在 platform adapter。
- NFR-006：大结果集不能在每次按键时重复扫描整个文件系统；内置索引需有缓存和失效策略。
- NFR-007：界面支持键盘焦点、可读 aria-label、可见 focus 状态和 reduced motion。
- NFR-008：不新增渲染层构建步骤；新增代码遵循当前原生 JS 和 Node test 风格。

## Data Requirements

建议新增数据键，不修改现有结构：

- `notch-launcher-settings-v1`：启动器来源、快捷键和行为偏好。
- `notch-launcher-favorites-v1`：结果 ID 集合或带来源的收藏记录。
- `notch-launcher-aliases-v1`：结果 ID 到别名的映射。
- `notch-launcher-usage-v1`：最近执行时间、次数和失败计数；可限制记录数量。
- `notch-launcher-extensions-v1`：已安装扩展的 manifest 摘要、目录、启用状态和诊断状态。
- `workspace/extensions/<extension-id>/`：扩展私有数据；不允许扩展通过路径逃逸。

已有键 `notch-home-commands`、`notch-note-archive-v1`、`notch-todo-data`、`notch-link-groups` 和剪贴板历史保持原样。

## Integrations

- Electron `globalShortcut`：启动器专用快捷键。
- Electron `BrowserWindow` / `webContents`：复用窗口，但增加 launcher 状态和安全 IPC。
- Electron `shell.openPath` / `shell.openExternal`：通过 allowlist 打开应用、路径和 URL。
- Electron `utilityProcess` 或受控子进程：扩展进程运行。
- 现有 `preload.js` contextBridge：暴露最小 launcher API。
- 现有 workspace persistence：迁移新增 LocalStorage 键和扩展目录。

## Permissions And Roles

- 普通用户：搜索、执行安全内置动作、管理自己的收藏/别名和本地扩展。
- 扩展：只能通过 manifest 声明的宿主动作和权限工作；不能访问 renderer DOM、Electron IPC 或整个工作区。
- 宿主：校验 manifest、管理进程、执行 allowlist 动作、记录错误和控制资源。
- 系统权限：扩展使用网络、文件、shell 或辅助功能时仍受操作系统权限约束；宿主必须在 UI 中解释。

## Edge Cases

- 快捷键已被系统、输入法或其他应用占用。
- 启动器打开时用户切换屏幕或窗口；应固定当前目标屏直到关闭。
- LocalStorage 损坏、扩展目录缺失、manifest JSON 无效或版本不兼容。
- 两个扩展命令 ID 冲突、别名冲突、结果 ID 不稳定。
- 扩展返回重复结果、超长标题、非法图标路径、未知动作或超大输出。
- 查询快速变化，旧响应晚于新响应返回；只能接受当前 request ID 的结果。
- 应用已卸载、链接失效、笔记已删除或待办被其他页面修改。
- 主动作启动外部应用后窗口焦点恢复失败。
- 用户卸载扩展时仍有进程运行或仍有未完成请求。
- 无扩展、无内置结果、扩展全部禁用时的空状态。

## Success Metrics

- 80% 的常用工作区目标可在 2 次按键内从启动器定位。
- 从快捷键到可输入状态的主观延迟低于当前展开工作台路径。
- 试用用户可以在 3 分钟内安装并运行样例扩展。
- 扩展超时/崩溃不会造成应用崩溃或需要重启。
- 现有待办、笔记、链接、常用指令和剪贴板回归测试全部通过。

## Acceptance Criteria

- AC-001：配置启动器快捷键后，从任意应用唤出并自动聚焦搜索框。
- AC-002：输入内置资源关键词，结果按匹配度排序；Enter 执行主动作。
- AC-003：上下键、Home/End、Escape、动作面板均可完整键盘操作。
- AC-004：收藏、别名和最近使用在重启及工作区迁移后仍保留。
- AC-005：旧 `notch-home-commands` 仍只能复制和编辑，数据不被改写为脚本。
- AC-006：本地无效 manifest、路径穿越 zip 和权限字段错误会被拒绝并给出提示。
- AC-007：样例 process 扩展可以响应查询和执行；超时、崩溃、非法 JSON 都能隔离回收。
- AC-008：扩展不能通过返回值触发未声明或不允许的宿主动作。
- AC-009：macOS 和 Windows 的应用发现、链接打开和窗口定位均通过平台适配器测试。
- AC-010：完整 `npm test`、语法检查和至少一组 Electron 启动器场景通过。

## Open Questions

- OQ-001：启动器和当前工作台是否使用两个独立快捷键，还是复用一个快捷键并通过设置选择默认模式。
- OQ-002：MVP 是否加入应用发现；若加入，Windows Start Menu 和 macOS `/Applications` 的扫描范围如何配置。
- OQ-003：首版是否接受 zip 安装；本地目录安装足以支持内部开发验证。
- OQ-004：是否要求扩展包签名；在未建设在线商店前，建议先保留明确的“本地代码可执行”警告。
