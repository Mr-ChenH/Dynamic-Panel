# AI 对话本地资料上下文实施报告

## 范围

第二阶段先交付显式本地资料上下文，不同时引入持久会话、联网搜索或工具调用。用户可为单条消息选择最多 3 份文字资料，来源包括笔记、录音转写、待办、链接和文字/URL 剪贴板；图片剪贴板、录音音频和笔记图片字节不进入资料列表。

## 交互

- 输入区回形针按钮打开资料选择器。
- 选择器支持全部、笔记、录音、待办、链接、剪贴板六个范围和标题/正文搜索，展示结果数与选择上限。
- 已选资料在输入区显示可移除标签；发送后的用户消息保留静态来源标签。
- 发送后立即清空下一条草稿的资料标签，不会把上一条资料隐式带到下一条消息。
- 资料与问题封装超过 12,000 字符时禁用发送；选择器将无法加入的资料标记为超过上限，不静默裁剪正文。
- 停止或失败不进入成功历史；重试继续使用该轮发送时冻结的资料，即使原笔记随后被编辑或删除。

## 数据与安全

`renderer/chat-context.js` 同时供浏览器和 Node 使用，统一资料类型、去重、最多 3 份、搜索排序和消息封装。`NotchNotes`、`NotchTodo`、`NotchWorkspace` 和 `NotchClipboard` 只导出各自可用于聊天的文字快照，不导出附件字节、本地绝对路径、凭据或图片数据。

渲染层通过 `context.sources` 提交来源快照。`ai/schema.js` 在主进程重新校验来源类型、ID、标题、正文、重复项、数量、总字符数和请求字节数。`ai/prompts.js` 将来源序列化为 JSON，并在 system prompt 中明确其为不可信参考数据，禁止把资料内的命令、角色声明或提示词当作用户指令。

仅完整成功轮次会把包含资料 JSON 的用户消息写入后续有界历史。问题、当前资料和历史合计不超过 12,000 UTF-16 code units；超过边界时按完整轮次移除最旧历史，不裁剪当前资料。

## 验证

- `npm test`：184 项领域/结构测试，183 通过，1 项 POSIX 行为在 Windows 预期跳过，0 失败。
- 三个 Electron 场景全部通过，语法检查包含 `renderer/chat-context.js`。
- Electron 验收确认：选择器打开与搜索、资料标签、请求仅携带所选笔记、发送后清空待发送标签、用户消息来源标识、原笔记变化后重试仍使用冻结正文、成功资料进入下一轮历史。
- 视觉截图：`dist.noindex/home-chat-context-review.png`。

## 仍未包含

- 多会话本地历史、命名、搜索、归档和删除。
- 笔记图片、剪贴板图片、文件附件或录音音频理解。
- 联网搜索、可核验引用或自动工具调用。
- 长回答独立预览及从回答提取待办的确认流程。
- 真实厂商对资料内提示注入的质量测试；当前只证明应用边界和提示词隔离策略，不能把模型行为视为安全执行环境。
