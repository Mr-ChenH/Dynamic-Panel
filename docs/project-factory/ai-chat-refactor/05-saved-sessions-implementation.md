# AI 对话工作区会话实施报告

## 已交付

- 默认对话继续保持临时状态，未确认前不创建持久化键。
- 顶栏新增保存、历史和新建操作，并明确显示“仅本次会话”“已保存到当前工作区”或“未保存更改”。
- 首次保存先打开历史抽屉，展示消息、回答和资料文字快照的保存范围；用户二次确认后才写入。
- 历史抽屉支持对话全文搜索、按更新时间排序、切换、行内重命名、二次确认删除和新建临时对话。
- 已保存会话在成功、停止或失败轮次结算后自动保存；流式中间态不写入。
- 刷新后恢复用户消息、Markdown 回答、资料标签、停止/失败状态、回复操作和当前模型上下文。
- 重试记录保存原轮次上下文和资料快照；原笔记变化后，刷新再重试仍使用冻结正文。
- 存储失败或容量超限后保留内存内容、显示“未保存更改”，并阻止静默切换或新建造成数据丢失。

## 数据与边界

共享领域模块为 `renderer/chat-sessions.js`，存储键为 `notch-ai-chat-sessions-v1`。数据通过现有 LocalStorage 快照进入当前工作区的 `workspace.json`，不新增主进程文件接口。

- 最多 30 个会话。
- 每会话最多 30 个已结算回复。
- 单会话最多 512,000 UTF-16 code units。
- 全部会话最多 2,000,000 UTF-16 code units。
- 标题最长 48 字符。
- 会话记录不包含附件字节、图片、音频、API Key、本地绝对路径或诊断数据。
- 容量超限时拒绝当前写入，不自动淘汰或覆盖已有会话。
