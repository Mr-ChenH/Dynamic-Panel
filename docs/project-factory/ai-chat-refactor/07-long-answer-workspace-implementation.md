# AI 长回答工作台实施报告

## 已交付

- 新增 `renderer/chat-reader.js`，集中处理长回答资格、Markdown 标题提取、笔记标题和待办来源边界。
- 完整成功回复满足 600 字符、2 个 Markdown 标题或 18 行任一条件时，显示长回答工作台入口；停止、失败和生成中回复不显示。
- 阅读工作台覆盖聊天内部区域，提供安全 Markdown 正文、标题大纲、全文复制、选区复制、代码复制、保存笔记、撤销保存和待办提取。
- 大纲从安全渲染 DOM 读取标题文本，点击可定位正文；围栏代码中的伪标题不会进入领域分析或渲染大纲。
- 保存笔记复用原回复的 `savedNote` 与互斥状态，阅读工作台和消息操作保持同步。
- 待办提取优先使用完全位于正文中的显式选区，否则使用全文；来源超过 12,000 UTF-16 code units 时拒绝且不截断，合规来源进入既有候选预览、证据校验、批量保存和撤销流程。
- 返回阅读视图后保留会话、消息、聊天滚动位置和输入草稿；切换会话、新建对话、切换工作区、收起面板或页面卸载会关闭工作台。
- 阅读视图使用非模态 `region` 语义，顶层导航保持可用；原生 Escape 优先返回对话，不会误收起面板。AI 待办预览关闭后恢复到触发按钮。
- 700px 以下大纲改为横向导航，520px 下工具栏、正文和工作台无横向溢出。

## 安全边界

- 模型 HTML 不进入 DOM；正文继续由 `renderer/markdown.js` 通过 DOM API 和 `textContent` 构造。
- 模型外链继续经主进程公网 HTTP/HTTPS 与 DNS 校验，代码和正文复制继续走现有剪贴板 IPC。
- 阅读视图不创建新的聊天请求，也不自动保存笔记或待办。
- 待办提取继续使用统一 AI 网关的配置代次、并发、取消、超时、SSE 完整性、响应大小和证据规则。

## 验证

- `tests/chat-reader.test.js` 覆盖三种长回答条件、与 Markdown 渲染器一致的合法代码围栏、标题规范化、选区优先和 12,000 字符拒绝边界。
- `tests/renderer-structure.test.js` 固定阅读视图非模态语义、脚本加载、Escape 接口、焦点恢复和既有 AI 复用入口。
- `tests/startup.electron.js` 使用超过 12,000 字符的假模型回复验证入口状态、安全 Markdown、大纲滚动、全文/选区/代码的真实剪贴板内容、原生 Escape、Tab/Shift+Tab、待办全文与选区来源、候选批量保存/撤销、预览焦点恢复、笔记保存/撤销同步、草稿恢复和 520px 布局。
- `npm test` 通过：190 项领域/结构测试中 189 通过，1 项 POSIX 行为因 Windows 预期跳过，0 失败；三个 Electron 场景和全部语法检查通过。
- 验收截图：`dist.noindex/home-chat-reader-review.png`。

## 未包含

- 不增加网页搜索、工具调用、跨应用上下文或后台任务。
- 不增加回答正文编辑、选区另存为独立笔记、待办自动写入或大纲持久化。
- 真实厂商超长输出质量、macOS 键盘/选区行为和不同 DPI 的人工验收仍属于跨平台实机验证。
