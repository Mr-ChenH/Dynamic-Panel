# AI 长回答工作台设计

## 目标

将结构复杂或篇幅较长的完整 AI 回复从聊天流中打开为独立阅读视图，降低长文滚动、定位和结果采用成本。工作台不发起新的聊天请求，不自动保存或执行操作。

## 进入条件

仅状态为 `complete` 的回复可以进入。满足以下任一条件时显示“打开长回答工作台”动作：

- 正文不少于 600 个 UTF-16 code units。
- 至少包含 2 个 Markdown 标题。
- 至少包含 18 行非空内容。

停止、失败和流式回复不显示入口。

## 界面

工作台覆盖聊天内部区域，保留应用顶层导航边界：

- 顶栏：返回、回答标题、字符数、全文复制、复制选区、保存笔记、提取待办。
- 左侧：从安全 Markdown 渲染结果生成的标题大纲；点击后滚动到对应标题。
- 正文：最大阅读宽度 820px，沿用聊天 Markdown、代码块复制和安全外链处理。
- 状态栏：显示复制、保存、选区、长度限制和同步结果。

在 700px 以下，大纲改为正文上方的横向导航；在 520px 下工具按钮保持固定尺寸，标题截断，不产生横向溢出。

## 操作

- 全文复制：复制完整原始 Markdown。
- 复制选区：仅当浏览器选区完整位于正文容器内时可用。
- 保存笔记：复用聊天回复已有的保存/冲突安全撤销状态，标题从回答首个有效标题或首行生成。
- 提取待办：有有效正文选区时使用选区，否则使用全文；来源超过 12,000 字符时拒绝并提示缩小选区。随后打开现有 AI 整理工作区的 `extractTodos` 流程，由用户检查证据、责任领域和截止时间后再保存。
- 返回：恢复原聊天滚动位置、草稿和当前会话，不修改对话历史。

## 安全与生命周期

- 正文继续通过 `renderer/markdown.js` DOM API 渲染，不解析模型 HTML。
- 大纲标题取自安全渲染后的 `textContent`，不把模型文本写入 `innerHTML`。
- 外链继续交给主进程公网 URL 校验；代码复制继续使用现有剪贴板 IPC。
- 工作区只引用当前内存中的稳定回复；切换会话、新建对话、工作区切换或页面卸载时关闭。
- 保存笔记与聊天消息上的同一回复动作共享状态，避免重复保存或撤销错位。
- 提取待办沿用现有主进程 AI schema、并发、超时、SSE 完整性和候选证据校验。

## 验收

- 短回答不显示入口，三种长回答判定均有领域测试。
- 标题大纲忽略围栏代码块中的伪标题，并保持稳定顺序。
- 点击大纲可定位对应安全渲染标题。
- 全文、选区和代码块复制可用；选区不在正文内时不能复制或提取。
- 保存笔记与原消息动作状态同步，并可撤销。
- 超过 12,000 字符的全文不能直接提取待办，合规选区可以进入既有候选预览。
- 停止和失败回复无入口。
- 520px 宽度无横向溢出。
