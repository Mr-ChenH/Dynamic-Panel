# AI 对话工作区会话设计

## 产品边界

默认仍创建临时对话，不写入持久化数据。用户主动点击“保存对话”后，当前对话升级为当前工作区会话；后续已结算轮次自动保存。工作区会话随现有 `workspace.json` 迁移，不上传云端，也不跨工作区自动合并。

保存会话会复制消息正文、模型回答和用户已选择资料的冻结文字快照。界面在首次保存前明确说明这一点。API Key、模型诊断、附件字节、本地绝对路径、图片和音频不进入会话记录。

## 数据约束

存储键：`notch-ai-chat-sessions-v1`。

- 最多 30 个会话。
- 单会话序列化后最多 512,000 UTF-16 code units。
- 全部会话序列化后最多 2,000,000 UTF-16 code units。
- 标题最长 48 字符，默认取首条用户问题的首行。
- 单会话最多保留 30 个已结算回复记录。
- 每个回复记录保留问题、最多 3 份资料快照、该次请求使用的最多 6 轮上下文、回答、成功/停止/失败状态和时间。
- 达到容量时拒绝当前写入并显示错误，不自动淘汰、截断或覆盖其他会话。
- 流式中的未完成状态不写入存储；停止或失败结算后可保存，并继续支持重试。

## 界面

对话顶栏增加：

- 当前会话标题。临时会话显示“临时对话”，保存后显示可重命名标题。
- 保存按钮。临时会话有内容时可用，保存后显示已保存状态。
- 历史按钮。打开工作区会话抽屉。

会话抽屉提供搜索、按更新时间排序的会话列表、打开、行内重命名和删除确认。切换会话前取消活动请求；未保存的临时会话不隐式持久化。新建按钮始终创建新的临时对话。

## 生命周期

- 新问题成功、失败或停止后，将稳定回复记录加入当前会话内存。
- 当前对话已保存时，每次稳定变更自动写入存储。
- 重试在同一问题组下新增回复版本，并复用原请求上下文及资料快照。
- 打开历史会话时，从规范化记录重建消息、状态、操作按钮和后续模型上下文。
- 工作区切换按现有应用生命周期取消请求并重新加载目标工作区的数据。
- 存储写入失败或容量超限时，内存会话继续可用，顶栏显示“未保存更改”，不会谎报成功。

## 验收

- 临时会话在未点击保存前不产生存储键。
- 保存后刷新渲染页仍可恢复消息、Markdown、资料标签、停止/错误状态与重试。
- 搜索、切换、重命名和二次确认删除可用。
- 新建临时会话不删除已保存历史。
- 30 个会话、单会话和总字符边界均有领域测试。
- 损坏、未知字段或旧版本数据不会阻止聊天启动。
- 520px 内容宽度下抽屉和行内编辑不横向溢出。
