# AI 对话模块市场研究

## 研究目标

为 TO-DO Panel 的首页 AI 对话重构寻找成熟交互模式。目标不是复制一个通用聊天网站，而是在 1240 x 540 的本地桌面工作台里建立清晰、可恢复、明确受控的临时对话体验。

当前产品边界继续有效：用户主动发送；默认不读取工作区；不自动调用工具；不自动保存笔记或待办；会话只保存在内存；失败、取消或不完整结果不能进入成功上下文；所有模型请求继续经过统一主进程安全网关。

## 代表产品

### Raycast AI Chat

Raycast 将一次性问题和持续对话分成 Quick AI 与 AI Chat 两个层级。完整聊天强调持久历史、上下文附件、模型选择和消息恢复操作。其成熟细节包括：

- 输入框通过附件按钮或 `@` 显式添加文件、笔记、剪贴板、浏览器标签页和当前窗口等上下文。
- 消息可编辑并从该点重新生成；最后回复可重试；长用户消息自动折叠。
- 生成中可以停止，还可排队或引导后续消息。
- 标题栏承载会话与模型信息，消息区保持单一阅读主线。
- 代码块独立提供复制和换行控制。
- 长对话压缩会显示明确的“正在总结 / 已总结”生命周期，而不是静默丢弃上下文。

对本项目最有价值的是“显式上下文 + 可恢复消息 + 快速入口/完整会话分层”。持久历史、工具调用和排队发送不应在首轮照搬。

来源：https://manual.raycast.com/ai/ai-chat

### Claude

Claude 使用 Projects 管理独立的知识、说明和记忆边界，并通过 Incognito Chat 明确表达临时会话。Artifacts 把较长、需要继续编辑或导出的结果移到聊天右侧独立工作区，并保留版本选择。

对本项目最有价值的是：

- 在界面中明确说明当前会话是否保存、使用什么上下文，而不是把隐私规则藏在设置里。
- 聊天用于探索，值得编辑、保存或继续加工的结果进入独立结果面板。
- 项目或上下文边界必须可见且隔离。

本项目已有 AI 内容整理预览工作台，因此后续可以将“保存为笔记 / 提取待办”接入现有预览与撤销链路，不需要重新实现通用 Artifact 平台。

来源：https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them

来源：https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context

### ChatGPT

ChatGPT 的成熟模式包括流式回答、停止、重试、编辑消息、临时聊天、Projects 和 Canvas。Projects 承载持续上下文，Canvas 承载需要编辑的长内容，使消息流不必同时承担对话、文档编辑和结果交付三种职责。

对本项目最有价值的是“对话与产物分离”以及生成后的重试/编辑。完整项目体系、跨设备历史和复杂工具栏超出当前本地临时会话范围。

来源：https://help.openai.com/en/articles/6825453-chatgpt-release-notes

来源：https://help.openai.com/en/articles/10169521-projects-in-chatgpt

### Perplexity

Perplexity 把 Web、Academic、个人文件等来源范围作为输入前的显式选择，并在回答中提供可核验引用。Threads 和 Spaces 分别承担单次研究脉络与长期主题组织。

对本项目的启示是：只有实际接入可追溯搜索或本地材料检索时才展示来源；普通模型回答不能使用伪引用或模糊的“已联网”状态。未来接入网页或本地资料时，来源选择应放在输入区附近，并逐条显示真实材料。

来源：https://www.perplexity.ai/help-center/en/articles/10354769-what-is-a-thread

### Microsoft Copilot

Copilot 将“添加内容和代理”放在输入区，用户主动选择文件或知识来源。官方文档同时明确上传范围、存储和可用边界。

对本项目的启示是：笔记、录音、待办、链接、剪贴板或当前窗口都应由用户逐次选择并形成可移除的上下文标签，不能因为应用本地已有数据就默认发送。

来源：https://support.microsoft.com/en-us/microsoft-365-copilot/analyze-an-uploaded-document-in-copilot-chat

来源：https://support.microsoft.com/en-us/microsoft-copilot/file-upload-in-microsoft-copilot

## 市场共识

成熟产品大体收敛到以下模式：

1. 空态提供少量与当前产品有关的起始建议，而不是一个巨大的空白消息区。
2. 标题栏显示会话身份、模型或模式、上下文/隐私边界，新建与清理属于次级操作。
3. 用户消息紧凑区分，助手回答以宽松的文档排版呈现；不要把长回答塞进聊天气泡。
4. 输入框固定在底部并自动增高；发送、停止、附件/上下文使用明确图标和工具提示。
5. 请求发送后立即保留用户消息，并显示等待首个 token 的状态；流式阶段提供停止。
6. 失败、超时和取消必须保留问题及已发生的生命周期，提供原位重试；不能让一次失败看起来像从未发送。
7. 完整回答提供复制、重试和继续处理；代码块、表格、列表使用安全 Markdown 排版。
8. 上下文、来源、工具和记忆必须真实、可见、可移除。未接入的能力不能通过装饰性控件暗示存在。
9. 自动滚动只在用户位于底部附近时跟随；用户回看旧消息时不能被新 token 拉走。
10. 长内容和可交付结果适合进入独立预览或编辑面板，而不是无限拉长消息流。

## 当前模块差距

现有实现已有以下可靠基础：统一安全网关、SSE 增量事件、停止、输入与上下文大小限制、最近六轮上下文、配置代次校验、会话污染防护、接近底部时才自动跟随、纯文本渲染避免 HTML 执行。

主要差距：

- 空态只有一句提示，约 300px 的首屏空间没有形成有效起点。
- 标题栏只有“AI 对话”和清空/返回，默认厂商、模型、临时会话与上下文范围不够清晰。
- “清空”作为高频可见按钮过于突出，而“新对话”概念缺失。
- 用户和助手只靠“你 / AI”文字区分，助手长回答缺少 Markdown、代码块和段落层级。
- 生成时输入框完全只读，不能准备下一条草稿。
- 请求失败会同时删除用户消息和回复；停止也删除本轮，缺少原位错误状态和重试入口。
- 完成回复只有文字按钮“复制回复”，缺少图标化消息操作、重试和显式保存入口。
- 最近六轮裁剪是静默发生的，用户只在完成后看到泛化提示。
- 没有显式选择应用内资料作为上下文的能力，但也不能提前画出不可用的附件控件。
- 会话不持久化是有意约束，但视觉上更像“功能缺失”，需要以“临时对话”正面表达。

## 推荐方向

采用“临时工作会话”而不是“通用聊天网站”的产品定位。

### 页面结构

- 顶栏：返回、临时对话标题、当前厂商/模型、`仅本次会话` 状态；右侧使用图标按钮提供新对话和更多操作。清空放入更多菜单或二次确认，不作为最醒目的动作。
- 消息区：内容列最大宽度约 820px，助手回复不使用厚重气泡；用户消息使用紧凑背景。空态显示 3 至 4 个工作台相关的起始提示，例如规划今天、整理想法、解释问题、拆解行动项。
- 输入区：固定底部、自动增高，主按钮在发送与停止之间原位切换；在没有实际上下文能力前不显示附件按钮。模型与隐私信息在输入区上方保持可见但克制。
- 消息操作：用户消息支持编辑并重新发送；完整助手回复支持复制、重试、保存为笔记。保存必须进入已有预览/保存/撤销链路。

### 生命周期

- 提交后立即固定用户消息，并创建等待状态。
- 首个 token 到达后切换到流式回答，保持当前滚动跟随策略。
- 停止时保留已生成文本并标记“已停止，不计入上下文”；无文本时保留问题和可重试状态。
- 失败时保留问题，助手位置显示简短错误及重试按钮；输入草稿不丢失。
- 重试生成新版本，不静默覆盖旧答案；首版可以仅保留上一版本并提供版本切换。
- 上下文被裁剪前显示“将使用最近 N 轮”或范围提示，不在完成后才说明。

### 视觉语言

- 延续当前黑灰工作台，不使用大面积品牌渐变、发光球或营销式欢迎页。
- 使用一种温和主强调色表达发送/流式状态，错误、停止和上下文分别使用独立状态色。
- 助手回答使用 15px 至 16px 正文、舒展行高和稳定的 Markdown 标题/列表/代码样式。
- 消息操作默认低对比，悬停或键盘聚焦时出现；所有图标提供 tooltip 和 aria-label。
- 固定输入区高度边界和消息内容宽度，流式更新不能改变外层布局。

## 建议范围

### 第一阶段：应立即实现

- 重做空态、顶栏、消息排版和固定输入区。
- 显示当前默认厂商/模型与明确的临时会话边界。
- 安全 Markdown 渲染，代码块独立复制。
- 保留失败/停止轮次，提供重试。
- 回复操作改为复制、重试、保存为笔记。
- 输入框自动增高，生成中保留可编辑草稿，发送按钮原位切换为停止。
- 保留 12,000 字符、六轮上下文、全局并发和严格 SSE 生命周期。

### 第二阶段：有明确需求后实现

- 用户显式选择当前笔记、录音、待办、链接或剪贴板作为单条消息上下文。
- 多会话本地历史、搜索、命名、归档与删除。
- 长回答进入内容整理预览面板，支持保存待办与笔记。
- 真实搜索来源和引用展示。

### 暂不实现

- 自动读取当前工作区、当前窗口或剪贴板。
- 自动执行工具或修改用户数据。
- 伪造联网、来源、记忆或推理状态。
- Raycast 的 steer/queue、Claude 的完整 Artifacts 平台或 ChatGPT 的跨设备 Projects。

## 结论

最适合 TO-DO Panel 的不是缩小版 ChatGPT，而是 Raycast 的快速入口与完整会话分层、Claude 的对话/产物分离、Perplexity/Copilot 的显式来源边界组合。第一阶段应优先解决空态、消息可读性、失败恢复、模型透明度和输入区状态；持久历史、应用资料上下文和联网引用留到第二阶段，避免一次重构突破现有隐私与安全边界。
