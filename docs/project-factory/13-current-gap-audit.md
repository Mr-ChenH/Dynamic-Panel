## 当前缺陷

### B-001 / 高：普通路径入口仍接受 Windows 可执行类型

证据：`launcher/paths.js:6` 使用扩展名拒绝列表；没有 `.cpl` 等 Windows 可执行关联类型。本轮创建仅含普通文字的临时 `audit.cpl`，调用 resolveLaunchPath 返回非空对象（CPL_ACCEPTED true）。未执行该文件。

`main.js:1412` 复核使用同一校验，然后 shell.openPath。有效 CPL 可作为控制面板模块执行，因此当前“脚本/可执行文件不走此入口”的说明不成立。应采用更可靠的文件类型/关联策略，不能认为继续补几个后缀就封闭了执行面。

### B-002 / 中：直接 URL 共用结果 ID

证据：`renderer/launcher.js:54` 的 withDirectUrl 对所有地址固定返回 `builtin:url`。

不同网址因此共享收藏、别名和 usage。给网址 A 设置别名，再输入网址 B，B 会继承 A 的配置。违反 FR-007 的资源稳定身份及收藏/别名语义。应以规范化后的 URL 生成身份，并明确是否持久化直接输入的目标。

### B-003 / 中：路径等临时结果收藏后无法从空查询恢复

证据：service 仅根据当前 queryText 派生路径；renderer 收藏仅保存 ID，没有目标快照或恢复 provider。本轮 service 探针先查存在的 example.txt 获得 path:*，再空查询返回 []。

界面对所有结果提供收藏，但路径、直接 URL、部分动态扩展结果不在空查询候选集合；重开时不会出现在收藏/最近列表，别名也不能独立找回目标。应为允许收藏的临时结果提供可验证的恢复信息，或限制不支持持久化的结果操作。

### B-004 / 中：长文本前缀匹配被负分过滤

证据：`launcher/domain.js` 对标题前缀使用 `6000 - title.length`，而搜索丢弃负分。renderer 允许最长 16000 字符标题（常用指令/剪贴板文本可进入该范围）。

本轮探针：标题为 7000 个 a，查询 a，searchLauncherResults 返回 0 条。模糊子序列也使用 `300 - title.length`，有同类问题。相关扣分需有界，不能让命中变成未命中。

### B-005 / 中：持久化失败仍反馈成功

证据：`renderer/launcher.js:21` 的 save 返回 false；管理页 `:247` 忽略返回值，随后显示“别名已保存”。动作面板同样继续 render 并关闭，覆盖错误；“移除记录”分三次写入，也没有失败汇总。

当 LocalStorage 配额满或写入异常时，用户可能误以为保存成功。此项为确定的代码路径分析，尚未进行生产 Electron 存储配额故障注入。

### B-006 / 中：偏好选项过期后可能重新抢回选中状态

证据：`renderer/launcher.js:92,126`。render 在原选项被过滤后回退首项，但 preferredId 没有同步更新；search 仅在 preferredId 为空或 selectedId 属于 remote 时更新。

若原选项 A 已被过滤，回退到本地 B，再输入使 A 重新出现，render 会重新选 A，而不是保留当前 B。此项为静态状态路径分析，需补生产输入序列回归；不能把“远端刷新保留偏好”直接等同于完整 FR-014。

### B-007 / 中：宿主动作失败未进入扩展运行诊断

证据：`launcher/service.js:184` 在取得动作时即记录 execute success；`main.js:1407` 随后才校验路径/公开 URL 并执行 shell/clipboard。

扩展可以合法返回 open-path 指向不存在的文件，或 open-url 指向非公开地址：UI 会报执行失败，但扩展运行历史仍为 success，error 为空。要区分“扩展进程成功返回”与“宿主动作成功”，并记录后者失败。此项为代码调用链证据，未做端到端故障注入。

## 规格冲突应单独处理

- 02 的 FR-034 要求禁止扩展任意写工作区，05 技术设计第 179/213 行却明确不限制 Node 自身 API、采用可信本地代码。当前实现符合后者，不能同时声称满足前者；需要统一规格，或另行实现真正的访问隔离。
- FR-038 允许应用设置明确保存在本机，不能仅据这一条认定“扩展必须自动迁移”。但是 02 的依赖说明与 05 的存储方案还要求扩展目录/用户选择的数据迁移，该子项尚未落实。安装授权不能随外来工作区被默认为已授予。
