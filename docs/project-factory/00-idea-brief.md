# Idea Brief

## Summary

为 Dynamic Panel 增加一个类似 Raycast 的可扩展启动器。用户可以从任意应用通过全局快捷键唤出搜索面板，输入关键词后统一查找本机应用、工作区内容、快捷链接和命令，并通过 Enter、方向键、Tab、Escape 完成启动、打开、复制和后续动作。

启动器与现有顶部工作台共用 Electron 主窗口、快捷键配置、工作区数据和视觉系统。它是一个新的工作模式，不改变现有首页、待办、笔记、链接、录制和密钥页面的入口。

扩展能力分层建设：首版支持本地安装、启用/禁用、声明式命令和最小的独立进程 JSON Lines 协议，用样例扩展验证查询、执行、超时和崩溃隔离；在线扩展商店、账号体系、签名分发和云同步后置。

## Target Users

- 主要用户：使用 Dynamic Panel 管理学习、创作、开发和生活事务，并希望减少窗口切换的个人用户。
- 高阶用户：愿意安装自己信任的本地扩展，以连接脚本、开发工具、网页服务或个人自动化流程的用户。
- 扩展作者：能够编写 JavaScript/TypeScript 或其他可执行程序，希望通过简单 manifest 将命令接入启动器的开发者。

## Goals

1. 让用户从任意应用以一次快捷键进入可搜索的本机工作入口。
2. 将现有工作区内容和未来扩展命令放到同一个结果列表中。
3. 保持键盘优先：搜索、上下选择、执行、返回、动作菜单都不依赖鼠标。
4. 让常用项目支持收藏、别名和最近使用排序。
5. 建立可演进的扩展协议，同时将不受信任代码与渲染层、主窗口隔离。
6. 在 macOS 与 Windows 共用产品模型，尊重两平台现有权限和路径边界。

## Must-Have Features

- 全局快捷键唤出和关闭启动器。
- 搜索输入框、模糊匹配、结果分组、键盘导航和空状态。
- 内置结果来源：应用、链接、指令、笔记、待办；剪贴板作为可选来源。
- 直接打开 URL、文件/目录和应用；复制文本指令；打开现有工作区项目。
- 结果收藏、别名和最近使用记录。
- 选中结果后的动作面板，至少包含执行、复制、收藏/取消收藏和打开来源页面。
- 本地扩展 manifest、安装/卸载、启用/禁用和命令发现。
- 扩展权限声明、超时、崩溃回收、日志和错误提示。
- 扩展设置入口与工作区迁移支持。
- 不破坏现有 `localStorage` 键和工作区文件结构。

## Constraints

- 现有项目为 Electron 44 + 原生 HTML/CSS/JavaScript，无渲染层构建步骤。
- IPC 必须通过 `preload.js` 的 contextBridge 暴露；渲染层不能 `require('electron')`。
- 当前主窗口有折叠/展开状态机、全局面板快捷键和 Windows 点击穿透形状，启动器不能破坏这些行为。
- 现有数据主要保存在 LocalStorage，媒体附件在工作区目录；扩展数据需要使用独立目录，不能让扩展任意读写整个工作区。
- macOS 13+ Apple Silicon 与 Windows 10/11 x64 共用代码。
- 首版不执行打包或发布；实现阶段仍需通过现有 `npm test` 和 Electron 场景测试。

## Assumptions

- 启动器默认复用当前面板的展开窗口和视觉风格，而不是创建第二个常驻窗口。
- 当前配置的面板快捷键继续负责打开工作台；启动器使用新的独立快捷键，默认建议 `CommandOrControl+Space`，若注册失败则由设置页提示重新配置。
- 首版的应用索引使用主进程扫描和缓存；macOS 应用目录与 Windows 开始菜单/桌面快捷方式采用平台适配器。
- 扩展首版面向本机可信用户，安装时明确展示其权限和执行能力；完全沙箱化属于后续版本目标。
- 旧首页“常用指令”仍然是可复制文本，不会被自动解释为可执行脚本。

## Open Questions

- 启动器默认快捷键是否采用 `CommandOrControl+Space`，以及是否允许与系统输入法快捷键共存。
- 首版是否把计算器、剪贴板和文件搜索一起加入，还是先聚焦工作区内容与应用启动。
- 扩展安装入口是否只支持选择本地目录，还是同时接受 `.zip` 包。
- 是否需要让启动器与现有面板快捷键共用一次唤出后再通过 Tab 切换模式。
- 是否需要同步提供扩展作者 CLI/scaffold，还是先稳定 manifest 和运行协议。
