## 访问模型与兼容性

原设计的“可信本地代码”政策保持；此次增加的是可验证的 Node 直接文件访问限制，落实 FR-034 的直接工作区 IO 禁止。网络不具备 OS 级隔离，Node 权限模型也不承诺对恶意代码实现完整安全沙箱。

旧扩展如果向代码目录写文件、调用 child_process 或使用原生插件，现在会被拒绝。扩展须向请求中的 context.storagePath 写自己的数据，使用宿主提供的受限动作。本轮样例扩展和生产 Electron 路径均已验证。

新增生产依赖 koffi 3.2.1（lockfile 锁定），用于跨平台原生焦点 API。electron-builder 已包含 launcher/**/*.js，生产依赖随应用依赖打包；未实际执行打包，原生模块在两平台安装包中的验证仍属发布前门禁。

## 验证结果

- npm test：143 个 Node case，142 通过，1 个 POSIX SIGTERM 场景在 Windows 跳过；3 组 Electron 场景、语法检查通过。
- Node 与 Electron 内置 Node 两种运行时，实际执行扩展证明：专属数据可写，外部文件读/写、代码目录写入和 child_process 均返回 ERR_ACCESS_DENIED。
- 原生 Windows API 只读调用通过；恢复策略测试验证：目标仍有效且前台属于本应用才恢复，用户切换后不抢焦点，一次性释放捕获目标。
- 数据迁移验证：选择性往返、其他扩展不变、错误 ID/路径/编码/文件目录冲突被拒绝、导入失败后原数据保留、junction 拒绝。
- 原生确认路由通过生产 IPC 测试（测试替换对话框返回）：取消不改变剪贴板，确认后才执行。
- 生产场景覆盖连续 Escape 保护；原有存储故障、导航、选中项和扩展生命周期回归继续通过。
- 测试 runner 限制并发为 2，避免多测试文件同时启动大量 Node/Electron 进程，导致与生产并发策略无关的资源争抢。产品启动/查询超时未放宽。

## 性能证据与限制

Windows 开发环境，应用缓存已预热，5 次通过生产 preload/native mode 的程序化打开：

- 最终一轮输入聚焦 6.2–8.2ms；
- 首结果下一帧 10.7–11.8ms；
- 前一轮更高负载样本分别为 10.9–23.7ms、12.6–78.9ms。

两轮所测路径均满足输入 150ms / 首帧 100ms 目标。样本不包含 OS 全局快捷键投递延时，不把它当成“任意外部应用到启动器”的完整验收。

## 尚需目标系统/发布环境验收

1. macOS 13+ Apple Silicon 的真实前台应用恢复、签名后 koffi 加载，以及 POSIX 忽略 SIGTERM 场景。
2. Windows 10 实机、真实跨应用全局快捷键与前台焦点恢复；当前 Windows 原生函数检查和策略测试不能替代完整用户场景。
3. 物理多显示器、菜单栏/任务栏适配及 OS 快捷键占用；完整 OS 唤出性能。
4. 两平台安装包内 Node 权限参数、原生依赖与数据导入/导出的发布验收。没有获得打包授权，因此未执行桌面打包。

商店、zip 扩展安装、全盘搜索、完整 MSIX/AUMID、拼音、签名扩展分发和完整 OS 沙箱属于原设计后置范围。本轮未将这些内容冒充已实现，也不把已实现的软件能力等同于全平台验收完成。
