# Sync MVP v1 Interface Map

> Status: implementation contract. Product behavior remains governed by [02-requirements.md](./02-requirements.md). This document maps that behavior to public server APIs and desktop IPC without changing the existing local schemas described in the [server research notes](../../../../Dynamic-Panel-Sync-Server/docs/project-factory/sync/01-research-notes.md).

## 1. Interface boundaries

```text
Account browser                       Electron renderer
  | cookie + CSRF                       | narrow preload API
  v                                     v
Web console API                    Electron main sync service
  | account scope                       | ClientKey header + installationId
  +------------------- HTTPS -----------+
                          |
                    Sync API / events
                          |
            PostgreSQL + S3-compatible objects
```

- API base is `/api/v1`; JSON uses UTF-8 and camelCase. Timestamps are RFC 3339 UTC strings.
- Production is HTTPS only. Explicit development mode permits HTTP only for `127.0.0.1`, `[::1]`, or a `localhost` name resolved and connected to loopback.
- Account endpoints authenticate an opaque `HttpOnly` cookie. Sync endpoints authenticate `Authorization: ClientKey <base64url-secret>`. Neither credential is accepted in a URL.
- IDs are opaque UUIDv7 strings. A cursor is an opaque, authenticated token containing only server-readable `{instanceId,spaceId,epoch,sequence,issuedAt}`; clients must not parse it.
- Every response has `X-Request-Id`; credential-bearing and one-time-secret responses also have `Cache-Control: no-store`.
- Unknown JSON properties are rejected on writes. Reads may add properties within the negotiated protocol version.

## 2. Common envelopes

Successful single-resource response:

```json
{"data":{"id":"0195..."},"requestId":"req_..."}
```

Paginated response:

```json
{"data":[{"id":"0195..."}],"page":{"next":"opaque-or-null","hasMore":false},"requestId":"req_..."}
```

Error response:

```json
{
  "error": {
    "code": "space_limit_reached",
    "message": "Active space limit reached.",
    "retryable": false,
    "details": {"current":10,"limit":10}
  },
  "requestId": "req_..."
}
```

`details` is allowlisted per error code. Authentication failures always use `401 authentication_failed`; they never distinguish username, account, client, space, binding, or key existence. Object authorization failures use the same `404 resource_not_found` shape whether the target is absent or belongs to another scope.

Stable error families:

| Family | Codes |
| --- | --- |
| Authentication | `authentication_failed`, `session_expired`, `recent_auth_required`, `csrf_failed`, `account_disabled`, `client_revoked`, `installation_mismatch` |
| Compatibility | `protocol_unsupported`, `schema_unsupported`, `instance_changed`, `cursor_expired`, `restore_epoch_changed` |
| Validation | `invalid_request`, `invalid_entity`, `invalid_reference`, `digest_mismatch`, `content_length_mismatch` |
| Conflict | `revision_conflict`, `operation_reused`, `name_conflict`, `restore_in_progress` |
| Resource | `space_limit_reached`, `client_limit_reached`, `technical_limit_exceeded`, `rate_limited`, `storage_unavailable` |
| Lifecycle | `space_inactive`, `upload_expired`, `category_disabled`, `job_not_ready` |

Retryable responses include `Retry-After` where applicable. `storage_unavailable` and `rate_limited` are retryable; schema, authentication, structural-limit, and validation failures are not.

## 3. Authentication contracts

### 3.1 Account session

The browser receives cookie `dp_session=<opaque>` with `HttpOnly; Secure; SameSite=Lax; Path=/`. Development loopback may omit `Secure`. All state-changing console requests require both the cookie and `X-CSRF-Token`, obtained from `GET /account/session`; Origin must match the configured console origin.

- Absolute session lifetime: 12 hours; idle expiry: 30 minutes; both configurable downward/upward by the administrator.
- `POST /account/reauthenticate` verifies the password and marks that server-side session as recently authenticated for 5 minutes. High-risk endpoints require this state.
- Passwords require at least 12 characters by default and are hashed with Argon2id. MVP has no MFA fields, endpoints, enrollment, recovery codes, or challenges.

### 3.2 Client Key and installation binding

A generated Key is 32 random bytes encoded base64url with prefix `dpk_v1_`. The database stores a keyed lookup fingerprint and an Argon2id verifier, never the Key. The prefix and lookup fingerprint permit indexed lookup without storing a reusable credential.

The desktop sends these headers on every sync/object request:

```http
Authorization: ClientKey dpk_v1_<secret>
DP-Installation-Id: <random UUIDv4 generated by this installation>
DP-Protocol-Version: 1
DP-App-Version: 1.1.0
DP-Platform: darwin-arm64
```

On the first authenticated `POST /sync/session`, the server atomically changes the client's binding from `unbound` to that `installationId`. A different installation receives the generic authentication response and creates a scoped audit event. A cloned installation with the same ID remains the same logical client; concurrent-use heuristics are reported in audit but do not invent a second `clientId`.

Rotation stores at most two active verifier generations for one client. The old generation expires immediately or at `overlapEndsAt <= now + 24h`. Installation reset always revokes every generation, clears the binding, and returns one new Key while preserving `clientId` and historical origins.

## 4. Discovery and health APIs

| Method and path | Auth | Purpose |
| --- | --- | --- |
| `GET /.well-known/dynamic-panel-sync` | none | Stable instance identity and compatibility discovery |
| `GET /api/v1/health/live` | none | Process liveness only |
| `GET /api/v1/health/ready` | admin network policy | Database and online object-store readiness, no tenant counts |
| `GET /api/v1/admin/health/backup` | admin CLI | Backup target, last verified point, and alerts |

Discovery response:

```json
{
  "instanceId":"0195...",
  "service":"dynamic-panel-sync",
  "protocol":{"min":1,"max":1},
  "recordSchemas":{"min":1,"max":1},
  "capabilities":["push-pull","websocket-invalidation","multipart-objects","exports"],
  "limits":{"jsonBytes":1048576,"operationsPerPush":100,"changesPerPull":500,"chunkBytes":8388608,"clientObjectTransfers":4},
  "serverTime":"2026-09-20T10:00:00.000Z"
}
```

Discovery never contains account or space information. Readiness returns only component states (`ok|degraded|down`) and stable error codes.

## 5. Account Web console API

### 5.1 Session and profile

| Method and path | Body / result |
| --- | --- |
| `POST /account/login` | `{username,password}` -> account summary and cookie; identical failure response for unknown user/bad password |
| `GET /account/session` | `{account,csrfToken,expiresAt,idleExpiresAt,recentAuthUntil}` |
| `DELETE /account/session` | Logout current session |
| `GET /account/sessions` | Recent login/session rows with coarse IP and user-agent, never tokens |
| `DELETE /account/sessions/others` | Revoke all except current; recent auth required |
| `POST /account/reauthenticate` | `{password}` -> `{recentAuthUntil}` |
| `PUT /account/password` | `{currentPassword,newPassword}`; revokes other sessions |

No registration endpoint exists.

### 5.2 Spaces

| Method and path | Contract |
| --- | --- |
| `GET /spaces` | Active/inactive/deleting spaces, per-space usage, `activeCount`, `activeLimit:10` |
| `POST /spaces` | `{name}`; normalized unique within authenticated account |
| `GET /spaces/:spaceId` | Summary, categories, clients, cursor age, conflicts, usage |
| `PATCH /spaces/:spaceId` | `{name? , status?:"active"|"inactive"}` |
| `GET /spaces/:spaceId/deletion-impact` | `{recordCount,objectBytes,activeClients,recoverableUntil}` |
| `POST /spaces/:spaceId/delete` | `{confirmationName}`; recent auth; creates recoverable deletion state |
| `POST /spaces/:spaceId/restore` | Restore within deletion retention |
| `POST /spaces/:spaceId/categories/:category/delete` | `{confirm:true}`; writes category tombstones; recent auth |

Name normalization is Unicode NFKC, trimmed, internal whitespace collapsed, and Unicode case-folded into `normalizedName`; the displayed name is preserved. Database uniqueness is `(account_id, normalized_name)` for non-purged spaces.

Usage response reports records, objects, referenced bytes, incomplete uploads, and observation time. It does not imply a business quota.

### 5.3 Clients and Keys

| Method and path | Contract |
| --- | --- |
| `GET /spaces/:spaceId/clients` | Client rows and `activeCount`, `activeLimit:10` |
| `POST /spaces/:spaceId/clients` | `{name}` -> client metadata plus one-time `clientKey` |
| `PATCH /spaces/:spaceId/clients/:clientId` | `{name}` only; immutable ID and scope |
| `POST /spaces/:spaceId/clients/:clientId/rotate-key` | `{overlapSeconds:0..86400}` -> one-time Key and expiry |
| `POST /spaces/:spaceId/clients/:clientId/revoke` | Revokes Key generations and closes realtime sessions |
| `POST /spaces/:spaceId/clients/:clientId/reset-installation` | Recent auth; revokes old Keys, clears binding, returns one-time new Key |

Client projection:

```json
{
  "clientId":"0195...",
  "shortId":"8N4K2P",
  "name":"MacBook Pro",
  "status":"active",
  "keyStatus":"active",
  "binding":{"status":"bound","firstConnectedAt":"..."},
  "platform":"darwin-arm64",
  "appVersion":"1.1.0",
  "createdAt":"...",
  "lastSeenAt":"...",
  "revokedAt":null
}
```

A one-time Key property is emitted only by a successful create/rotate/reset response. It is absent, not masked, on every subsequent GET. Those responses use `Cache-Control: no-store`; console JavaScript holds the value only in view memory and clears it on navigation.

### 5.4 Conflicts, audit, usage, and exports

| Method and path | Contract |
| --- | --- |
| `GET /spaces/:spaceId/conflicts?status=unresolved&after=` | Account-scoped conflict metadata and compared values |

| `POST /spaces/:spaceId/records/:entityType/:entityId/restore` | Restores retained tombstone as a new revision |
| `GET /usage` | Account aggregate plus space breakdown, observation only |
| `GET /audit?spaceId=&action=&after=` | Account-only audit, no payload bodies or secrets |
| `POST /spaces/:spaceId/exports` | Starts immutable manifest export; recent auth |

Audit event projection is `{eventId,occurredAt,actorType,actorId,action,targetType,targetIdPrefix,spaceId?,result,errorCode?,requestId}`. IP addresses are stored/returned only in truncated or keyed form according to deployment policy.

## 6. Desktop sync API

### 6.1 Connection preflight

`POST /sync/session` performs authentication/binding and returns:

```json
{
  "data": {
    "instance":{"instanceId":"0195...","serverTime":"..."},
    "identity":{"accountIdPrefix":"acct_7Q","spaceId":"0195...","spaceName":"Work","clientId":"0195...","clientShortId":"8N4K2P","clientName":"MacBook Pro"},
    "state":{"account":"active","space":"active","client":"active","restoreEpoch":3},
    "protocol":{"selected":1,"recordSchemaMax":1},
    "limits":{"jsonBytes":1048576,"operationsPerPush":100,"changesPerPull":500,"chunkBytes":8388608,"clientObjectTransfers":4},
    "usage":{"recordCount":187,"objectCount":31,"objectBytes":73400320},
    "categoryCounts":{"todo":{"records":42,"bytes":8100},"notes":{"records":72,"bytes":53100,"objectBytes":50300000}},
    "storage":{"database":"ok","objects":"ok"},
    "clockSkewSeconds":4
  }
}
```

The desktop compares returned instance, space, client, and restore epoch with its local binding before push. A mismatch blocks writes and starts the explicit rebind/full-reconcile flow.

### 6.2 Records and operations

Canonical record:

```json
{
  "spaceId":"0195...",
  "entityType":"note",
  "entityId":"01J...",
  "category":"notes",
  "schemaVersion":1,
  "revision":7,
  "updatedAt":"2026-09-20T10:00:00.000Z",
  "originClientId":"0195...",
  "deleted":false,
  "payload":{"title":"Plan","body":"...","imageObjectIds":["obj_..."]}
}
```

Client operation:

```json
{
  "operationId":"01J...",
  "entityType":"note",
  "entityId":"01J...",
  "category":"notes",
  "schemaVersion":1,
  "baseRevision":6,
  "kind":"upsert",
  "payload":{"title":"Plan","body":"...","imageObjectIds":["obj_..."]}
}
```

`originClientId`, `spaceId`, timestamps, revision, and cursor are not accepted in an operation. `kind` is `upsert|delete|resolveConflict`. Deletes have no payload. Entity payload schemas are versioned allowlists; object references must already be committed and authorized in this space.

| Method and path | Contract |
| --- | --- |
| `POST /sync/push` | `{operations:[...]}`; max 100 and 1 MiB JSON; independent per-operation results in one DB transaction per operation |
| `GET /sync/pull?cursor=<opaque>&limit=1..500` | Stable page of ordered changes and `nextCursor`; page uses a captured upper sequence |
| `POST /sync/reconcile` | `{categories,known:[{entityType,entityId,revision,deleted}],pageToken?}` -> authoritative differences; retains unsent outbox |
| `GET /sync/stats?categories=` | Counts/bytes for first-sync preview, no record payloads |

Push result:

```json
{
  "data": {
    "results": [
      {"operationId":"01J...","status":"accepted","record":{"entityId":"01J...","revision":7},"cursor":"opaque"},
      {"operationId":"01K...","status":"duplicate","record":{"entityId":"01K...","revision":2}},
      {"operationId":"01L...","status":"conflict","conflictId":"0195...","currentRevision":8},
      {"operationId":"01M...","status":"rejected","error":{"code":"invalid_entity","retryable":false}}
    ]
  }
}
```

A repeated `(spaceId,clientId,operationId)` returns the stored result. Reuse with different canonical request hash returns `operation_reused`. A conflict preserves incoming payload/version data and still advances the space change stream with a conflict event.

Pull result contains `changes`, `nextCursor`, `hasMore`, `upperCursor`, and `restoreEpoch`. Every page after the first carries the same signed upper sequence, so concurrent writes appear in a later pull and are never skipped. An expired sequence returns `410 cursor_expired` with no partial changes.

### 6.3 First-sync plans

`POST /sync/first-sync/plan` accepts local counts/digests by enabled category, and returns recommended `upload|download|merge`, impact counts/bytes, missing objects, and a short-lived `planId`. `POST /sync/first-sync/execute` accepts `{planId,mode:"upload"|"download"|"merge"}`.

Destructive `replaceRemote|replaceLocal` is separate:

1. `POST /sync/first-sync/recovery-point` creates and verifies a scoped recovery point.
2. Server returns `recoveryPointId`, impact, and `confirmationToken` bound to the identity and mode.
3. `POST /sync/first-sync/execute-destructive` requires all three plus explicit confirmation.

Cancellation invalidates the plan and does not mark the binding initialized. Rebuilding a local index never deletes valid local business data.

### 6.4 Realtime invalidation

`GET /sync/events` upgrades to WebSocket using the same authorization and installation headers. The Key is not a query/subprotocol value. The server sends only:

```json
{"type":"cursor-available","cursor":"opaque","restoreEpoch":3}
{"type":"connection-revoked","reason":"client_revoked"}
```

Messages contain no business payload. Clients send `{type:"ping"}` and receive `pong`; all other client messages are rejected. Notifications may be coalesced. Desktop always reconciles on startup, wake, network recovery, every 30 seconds by default, and after reconnect.

### 6.5 Object transfer

Object descriptor:

```json
{"objectId":"obj_0195...","digest":"sha256:<64-hex>","bytes":50321,"mimeType":"image/png","purpose":"note-image"}
```

Allowed purposes are `note-image|clipboard-image|screenshot`; allowed MIME is `image/png` for MVP. Client filenames and paths are never accepted.

| Method and path | Contract |
| --- | --- |
| `POST /objects/uploads` | Descriptor -> `{uploadId,chunkBytes,expiresAt,completedParts}`; does not reveal cross-space existence |
| `PUT /objects/uploads/:uploadId/parts/:partNumber` | Exact bounded chunk, `Content-Digest`; idempotent by part number+digest |
| `GET /objects/uploads/:uploadId` | Resume state for this client/space |
| `POST /objects/uploads/:uploadId/complete` | Verifies aggregate bytes/SHA-256 then commits object |
| `DELETE /objects/uploads/:uploadId` | Cancels this upload |
| `GET /objects/:objectId` | Authorized stream with Range support and digest/length headers |

The server may internally reuse bytes, but upload initiation has scope-independent response shape/timing padding and always creates a space-local authorization row. Download writes to a desktop temp file and atomically renames only after verification. Parent metadata is not projected as complete until all referenced objects are committed.

Technical boundaries, not business quotas: headers 32 KiB, JSON 1 MiB, push 100 operations, pull 500 changes, chunk 8 MiB, at most 4 object transfers per client, 10,000 chunks per upload, 30-second request timeout excluding streamed bodies, and incomplete-upload expiry at 24 hours. There is no account/space byte, image-count, or full-image-size business quota.

## 7. Entity schema registry

| `entityType` | Category | Stable identity / payload contract | Merge |
| --- | --- | --- | --- |
| `todo` | `todo` | One item; `quadrant:P0..P3`, text, done, deadline, reminded state, sortKey | Field merge; conflicting fields retained |
| `todoCategory` | `todo` | Stable `P0..P3`; display name only | Field LWW/conflict record |
| `note` | `notes` | Title, Markdown body with logical image refs, category/tag IDs | Body/title conflict copy |
| `noteTaxon` | `notes` | Category/tag entity, parent reference | Field merge |
| `link` | `links` | URL, title, description, tags, favorite/read, note, group ID, sortKey | Field merge |
| `linkGroup` | `links` | Name, sortKey | Field merge |
| `preference` | `preferences` | Only `theme`, `features`, `defaultTab`, one key per record | Server-accept-order LWW |
| `clipboardEntry` / `clipboardFavorite` | `clipboard` | Normalized text/URL/image ref and favorite relation | Append/dedupe + tombstone |
| `screenshot` | `screenshots` | Complete screenshot metadata + PNG object | Field merge |
| `aiSession` | `aiSessions` | Existing bounded text snapshot only | Session conflict copy |
| `financeWatchlist` | `finance` | Groups/assets and portable display fields only | Field merge |
| `command` | `commands` | User text command, no executable permission | Conflict copy |
| `launcherFavorite` / `launcherAlias` | `launcher` | Favorite/alias only, never extension code/storage/usage | Field merge |
| `weatherLocation` | `location` | Selected portable location | Field LWW |

All IDs are assigned/stabilized in the desktop adapter before enqueue. Payload validators remove no unknown fields silently: invalid or future schemas are quarantined and surfaced. Absolute paths, encrypted vault blobs, API Keys, recording/recording transcript data, video, music state/files, shortcuts, auto-launch, workspace path, capture devices, hidden windows, diagnostics, drafts, caches, and extension code/permissions/storage are forbidden.

## 8. Desktop IPC and local service map

Existing `workspace:*` channels and `workspace.json` behavior remain unchanged. New channels belong in `main/ipc/sync.js`; preload exposes `notchAPI.sync`, never raw network or Key access.

| Preload method / IPC | Input -> result |
| --- | --- |
| `sync.getStatus` / `sync:get-status` | none -> binding identity prefixes, state, counts, last sync/error |
| `sync.testConnection` / `sync:test-connection` | `{baseUrl,clientKey,allowLoopbackHttp}` -> preflight projection; Key remains main-process memory until save |
| `sync.saveBinding` / `sync:save-binding` | tested connection token + categories + first-sync choice -> binding summary |
| `sync.setCategories` / `sync:set-categories` | allowlisted category booleans; returns impact preview/confirmation requirement |
| `sync.pause` / `sync:pause` | `{paused}`; never clears queues |
| `sync.runNow` / `sync:run-now` | none -> accepted/current generation |
| `sync.listConflicts` / `sync:list-conflicts` | pagination -> sanitized conflict rows |
| `sync.resolveConflict` / `sync:resolve-conflict` | conflict ID + decision/manual payload -> result |
| `sync.removeBinding` / `sync:remove-binding` | explicit confirmation -> removes local credential/state, not business data |
| `sync.cancelTransfer` / `sync:cancel-transfer` | transfer ID -> idempotent result |
| `sync.onStatus` / `sync:status` | subscription to non-secret status projection |

Main process owns HTTPS, `ws`, safeStorage, installation ID, durable queue, local object IO, backoff, and atomic apply coordination. Renderer adapters emit typed local mutations and apply validated remote records through existing domain stores. The renderer never receives the persisted Client Key.

Local binding key is `(instanceId,spaceId,clientId,workspaceId)`. Each binding has a separate SQLite file or namespace containing outbox, cursor/epoch, conflicts, object maps, transfer checkpoints, and adapter entity maps. Switching credentials first pauses the current generation and commits queue/checkpoints; rows are never relabeled to the new identity.

## 9. Administrator CLI contract

Executable name in the server package: `dynamic-panel-sync`. Commands default to human-readable output; `--json` is stable and secrets are emitted only by commands that create/reset them.

```text
dynamic-panel-sync account create|list|disable|enable|delete|reset-password
dynamic-panel-sync limits show|set
dynamic-panel-sync usage show [--account <id>] [--space <id>]
dynamic-panel-sync backup configure|run|list|verify|status|prune
dynamic-panel-sync restore stage|inspect|apply
dynamic-panel-sync audit query
dynamic-panel-sync doctor
dynamic-panel-sync migrate status|up
dynamic-panel-sync serve
```

Exit codes: `0` success, `2` validation/configuration, `3` authentication/authorization, `4` not found, `5` conflict/limit, `6` temporary storage/network, `7` verification failed, `8` migration incompatible, `10` unexpected. `--json` errors use the common error object and write data to stdout, diagnostics to stderr. Backup credentials and encryption keys are accepted through secret files/environment or interactive input, never command arguments.
