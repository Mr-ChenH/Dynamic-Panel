# 同步功能需求

> 状态：Sync MVP v1 产品边界与默认限制已确认。本文只定义行为与验收条件，不作为实现方案或技术选型。

## 1. 产品版本

**Sync MVP v1** 为 Dynamic Panel 增加可选的自托管多账号同步服务。一个服务实例可包含多个账号，每个账号可创建多个相互隔离的同步空间。账号用户在空间中添加客户端时，服务端为该客户端生成唯一 Key；桌面客户端填写服务端 URL 和自己的客户端 Key 后，只在所属空间内进行离线优先的近实时同步，服务端以该 Key 对应的客户端身份记录数据来源。服务端还负责执行可独立恢复的定时备份。

## 2. 问题陈述

Dynamic Panel 当前把渲染层状态保存为 LocalStorage 全量快照，并把媒体文件放在多个本地目录中。该方式适合单机使用和便携目录，但无法安全传播多设备更新与删除、处理并发编辑、续传大文件，也无法区分可携带数据、本机配置和秘密。

产品需要一份明确的多账号同步契约：账号之间以及同一账号的不同空间之间严格隔离；同一空间的每个客户端拥有独立认证 Key，空间内客户端共享同步历史，但每条写入的来源可由服务端可靠区分。同时保留现有本地 schema，防止旧客户端、敏感数据默认值、传输失败或备份错误造成静默丢失或泄露。

## 3. 目标

- `G-001` 在 macOS 和 Windows 设备间同步用户选定的内容，且不阻塞本地工作。
- `G-002` 正常条件下，在线设备在数秒内看到其他在线设备的变化。
- `G-003` 所有并发编辑在解决冲突或恢复期结束前均可找回。
- `G-004` 用户可明确控制敏感数据和大体积数据的同步范围。
- `G-005` 凭据、本机路径和设备专属行为不得进入同步数据。
- `G-006` 一个服务实例支持多账号，每个账号支持多个空间，同一空间支持多台客户端；账号和空间边界均可验证、可审计。
- `G-007` 服务端数据可从经过验证的定时备份中恢复。

## 4. 非目标

- `NG-001` 跨账号共享空间、团队成员协作、公开分享和单条数据 ACL。
- `NG-002` MVP 不提供针对服务端运营者的端到端加密。
- `NG-003` 不跨设备同步 API Key、密码或密钥库条目。
- `NG-004` 不提供逐字符的协同笔记编辑。
- `NG-005` 不复制本地音乐文件、音频录音、屏幕录制、启动器可执行扩展或任意工作区文件。
- `NG-006` 不替换现有本地优先持久化；没有服务端时应用仍须可用。
- `NG-007` 不把服务端实时副本当作备份的替代品。
- `NG-008` MVP 不开放账号自助注册，不接入 OIDC，也不提供跨账号成员邀请。
- `NG-009` MVP 不提供 MFA 注册、恢复或登录挑战。

## 5. 用户角色

- **账号用户：** 通过账号认证创建和管理多个个人空间、客户端、客户端 Key、结构名额与存储用量。
- **桌面用户：** 在多台 macOS/Windows 客户端使用同一个空间，希望离线修改也能最终同步。
- **服务端管理员：** 部署服务、管理账号生命周期、设置全局结构限制与备份策略、执行恢复。
- **安全敏感用户：** 要求账号和空间严格隔离、敏感分类默认关闭，并清楚了解每台设备会上传哪些数据。

## 6. 术语

- **账号：** 服务端中的顶级用户边界，拥有独立认证身份，可创建和管理多个同步空间。
- **同步空间：** 隶属于一个账号的隔离数据命名空间，拥有稳定 ID；一个账号可拥有多个空间，一个空间可包含多条预建客户端记录。
- **客户端：** 账号用户在某个空间内创建的同步来源身份，拥有不可变 `clientId`、显示名称、状态、创建时间和最后在线时间，对应一台逻辑桌面客户端。
- **客户端 Key：** 服务端为一个客户端生成的高熵不透明同步凭据，只能代表该客户端访问其所属空间，不能登录账号、枚举同账号其他空间或代表其他客户端。
- **本地绑定：** 一个本地工作区与一个远端客户端身份之间的关联；客户端 Key、outbox、游标和附件映射均属于该绑定。
- **记录：** 一条有类型的逻辑实体，例如笔记、待办、链接或偏好字段。
- **对象：** 由加密摘要寻址的二进制内容，例如笔记、剪贴板或截图 PNG 文件。
- **游标：** 服务端签发的、不透明的空间变更流位置。
- **删除墓碑：** 保留的删除记录，用于防止长期离线设备把已删除数据重新写回。
- **冲突：** 两次有效修改基于同一个旧版本，且无法在没有规则或用户选择时同时成为当前值。
- **备份：** 在线数据路径之外、可恢复到特定时间点的副本；生产环境还应与在线数据处于不同故障域。

## 7. 用户故事

- `US-001` 作为账号用户，我可以创建多个空间，并在每个空间中添加多个具名客户端；服务端为每个客户端分别生成只显示一次的 Key。
- `US-002` 作为桌面用户，我可以填写服务端 URL 和分配给本客户端的 Key，测试连接并选择同步内容。
- `US-003` 作为账号用户，我可以查看每个空间的客户端、用量、同步状态和数据来源，单独轮换某个客户端 Key 或吊销该客户端，而不影响同空间其他客户端。
- `US-004` 作为桌面用户，我能看出当前绑定的是哪个空间，以及同步处于最新、待处理、暂停、离线、冲突或错误状态。
- `US-005` 作为桌面用户，我可以离线修改，并在重连后自动重试。
- `US-006` 作为桌面用户，首次同步时可以安全合并当前本地工作区与目标空间已有数据，而不会被静默覆盖。
- `US-007` 作为桌面用户，启用剪贴板或截图前能看到预计条目数和体积；一个剪贴板开关同时控制文字、收藏和图片。
- `US-008` 作为桌面用户，我可以查看并解决同一空间内其他客户端造成的并发编辑，且任一版本都不会丢失。
- `US-009` 作为桌面用户，我可以暂停同步、移除此设备或删除本地同步凭据，而不删除本地内容。
- `US-010` 作为服务端管理员，我可以禁用账号并查看安全审计事件，而不会误操作其他账号。
- `US-011` 作为管理员，我可以检查备份健康状态，并先恢复到隔离位置再恢复一个指定账号或空间。
- `US-012` 作为同一账号的用户，我可以创建“个人”和“工作”等多个空间，它们的记录、对象、设备和同步进度互不混合。

## 8. 功能需求

### 8.1 账号、空间与 Key 生命周期

- `FR-001` 服务端必须公开稳定的实例 ID，以及支持的同步协议和 schema 版本范围。
- `FR-002` 一个服务实例必须支持多个账号；账号是空间所有权、管理授权、结构名额、用量汇总和审计查询的顶级边界。
- `FR-003` MVP 账号只能由服务端管理员通过管理 CLI 创建、禁用、恢复和删除；不得开放匿名自助注册端点。
- `FR-004` 账号必须使用服务端本地用户名/密码认证，且与客户端 Key 分离；服务端不得保存可恢复的密码明文，桌面同步客户端也不得接收或保存账号密码。
- `FR-005` 已认证账号用户必须能列出、创建、命名、重命名、停用和删除本账号的多个同步空间，但不能查看其他账号的空间标识、名称或用量；空间名称在同一账号内必须唯一，每个账号最多同时拥有 10 个活动空间。
- `FR-006` 每个同步空间必须且只能属于一个账号。MVP 不允许跨账号转让或共享空间。
- `FR-007` 账号用户必须先在目标空间中创建具名客户端；服务端在创建或轮换该客户端凭据时生成至少具有 256 bit 随机熵的客户端 Key，明文只显示一次。
- `FR-008` 服务端只能保存账号密码和客户端 Key 的安全单向校验值，不得保存可恢复明文；任意两个活动客户端不得拥有相同 Key 或相同 Key 校验身份。
- `FR-009` 一个客户端 Key 必须且只能映射到一个不可变 `clientId`、一个同步空间和一个账号。它只授予该客户端在所属空间的同步权限，不得登录账号管理接口、枚举同账号其他空间或代表其他客户端。
- `FR-010` 客户端只能通过已认证连接的授权请求头发送客户端 Key。Key 不得进入 URL、查询参数、fragment、实时通道 URL、遥测字段或普通日志。
- `FR-011` 服务端接受同步请求时，必须从客户端 Key 的认证结果取得 `accountId`、`spaceId` 和 `clientId`；请求 payload 中自报的来源客户端字段不得覆盖该身份。
- `FR-122` 账号用户必须能按空间创建和查看客户端，并看到客户端名称、不可变短 ID、平台、应用版本、Key 状态、安装绑定状态、创建时间、最后在线时间和吊销状态；只能管理本账号空间中的客户端，每个空间最多同时拥有 10 个活动客户端。
- `FR-123` 吊销客户端 Key 后，该客户端下一次认证请求必须失败，现有实时连接必须关闭；该动作不得远程删除客户端本地内容，也不得影响同空间其他客户端。
- `FR-124` 客户端 Key 轮换必须作用于单个客户端，并支持立即失效或最长不超过 24 小时的可配置重叠期；同空间其他客户端 Key 必须保持不变。
- `FR-125` 认证失败响应不得暴露账号、空间、客户端或客户端 Key 是否存在，并必须受速率限制。
- `FR-126` 禁用账号后，账号管理会话及其全部空间的同步连接必须失效；数据按保留策略冻结，不得立即清除。重新启用账号后，空间须经过正常对账恢复同步。
- `FR-127` 停用空间后，该空间所有 push、pull、对象传输和实时连接必须停止，但同账号其他空间继续工作。
- `FR-128` 删除空间必须显示记录数、对象体积和已添加客户端，要求再次认证与明确确认，并在永久清除前创建可恢复状态或遵守删除保留期。
- `FR-129` 删除账号必须是独立的高风险操作，覆盖该账号全部空间、客户端 Key、客户端记录和审计关联；不得影响其他账号，并必须遵守备份与法定/配置保留策略。
- `FR-130` 所有管理和同步端点必须从已验证凭据推导账号、空间和客户端上下文，或验证请求中的 ID 属于该上下文；不能仅依赖客户端传入的 `accountId`、`spaceId`、`clientId` 或随机 ID。
- `FR-131` 服务端必须强制每账号最多 10 个活动空间、每空间最多 10 个活动客户端，并向 Web 控制台报告当前数量与剩余名额。MVP 不设置账号/空间对象总字节、图片数量或单图大小的业务配额。
- `FR-132` 同一空间内的不同客户端必须共享该空间的记录、对象、冲突、墓碑和变更流，但每个服务端接受的操作必须记录由认证 Key 确定的来源 `clientId`；不同空间必须拥有独立游标、实时主题、outbox 作用域和对象授权。
- `FR-133` 一个本地工作区最多绑定一个远端客户端身份。若同一应用安装使用多个客户端 Key，每个绑定的 Key、`clientId`、游标、outbox、冲突和附件映射必须隔离；切换 Key 前必须暂停并完成当前绑定的状态提交。
- `FR-135` 账号用户必须能修改密码、撤销其他管理会话并查看近期登录；服务端管理员可通过管理 CLI 发起受审计的密码重置，重置后必须强制用户设置新密码，且管理员不得读取原密码。
- `FR-136` 服务端管理员拥有账号生命周期和全局运维权限；账号用户只能管理本账号、空间、客户端、客户端 Key、用量、审计和导出。所有管理操作必须进行服务端授权，不得仅依赖界面隐藏。
- `FR-137` 账号或空间列表、搜索、错误消息和指标都必须避免通过数量、名称、ID、响应差异或对象摘要泄露其他账号/空间的存在。

### 8.2 客户端连接与认证

- `FR-012` 桌面客户端必须接受服务端基础 URL 和分配给它的客户端 Key；认证成功后必须显示客户端名称/短 ID 及目标空间名称/标识，避免使用错误身份或绑定错误空间。
- `FR-013` URL 校验必须拒绝内嵌用户名/密码、查询凭据、fragment 和不支持的协议。生产服务必须使用 HTTPS；回环 HTTP 只能作为显式开启的开发选项。
- `FR-014` “测试连接”必须在保存前检查 TLS、服务端身份、协议兼容性、客户端 Key 认证、来源 `clientId`、目标空间身份与状态、时间偏差提示、空间/客户端名额状态、存储可用性和服务能力。
- `FR-015` 正常同步流程不得提供“忽略证书错误”选项。
- `FR-016` 客户端 Key 必须存入操作系统安全存储。安全存储不可用时，可以提供仅当前会话有效的连接，但不得明文持久化。
- `FR-017` 客户端必须把本地同步状态绑定到服务端实例 ID、同步空间 ID 和 `clientId`，而不是只绑定 URL。相同 URL 后续返回不同实例，或输入的 Key 指向不同空间/客户端时，应停止同步并要求用户确认。
- `FR-018` 移除本地连接时，客户端只能删除本地 Key/绑定状态且默认不得删除本地业务数据；如需停止服务端访问，界面必须提示账号用户到 Web 控制台吊销对应客户端 Key。
- `FR-147` 每次桌面应用安装必须生成随机、稳定且不基于硬件指纹的 `installationId`，并把它与客户端 Key 的本地绑定状态一起持久化。
- `FR-148` 未绑定的客户端 Key 首次成功认证时，服务端必须原子地把对应客户端记录绑定到该 `installationId`，并记录首次连接时间与客户端平台/版本。
- `FR-149` 已绑定客户端 Key 从不同 `installationId` 发起认证时必须失败，并产生账号用户可见的安全审计事件；不得把请求记作新的来源客户端。
- `FR-150` 账号用户必须能对单个客户端执行“重置安装绑定”。重置必须撤销旧 Key、断开现有连接、生成新 Key，并保留原不可变 `clientId` 及历史来源归属。
- `FR-151` MVP 本地账号认证只使用用户名、高强度密码和可撤销 Web 会话，不得要求或提供 MFA 注册、恢复码、二次验证码或 MFA 登录挑战。

### 8.3 同步分类控制

- `FR-019` 首次上传前，客户端必须按分类显示开关、条目数、预计上传字节、敏感级别和依赖关系。
- `FR-020` 新连接默认启用待办、笔记、笔记分类与图片、链接和可携带偏好。
- `FR-021` 剪贴板、截图、已保存 AI 会话、位置和自定义命令必须默认关闭，并由用户显式启用。剪贴板是一个不可拆分开关，同时控制文字历史、收藏关系和图片附件。
- `FR-022` 笔记或截图等父级元数据未启用时，不得单独启用其附件；剪贴板文字与图片不得显示或保存为两个独立同步开关。
- `FR-023` 关闭分类后必须停止该分类后续上传和下载，但不得静默删除服务端或设备上已存在的数据。
- `FR-024` 用户可在二次确认后选择是否同时为服务端该分类数据写入删除墓碑。
- `FR-025` 分类选择必须是设备级配置，使工作设备可以排除敏感历史，而其他设备仍可启用。

### 8.4 变更模型与增量同步

- `FR-026` 同步必须以有类型的记录为单位，不得同步任意 LocalStorage 全量快照或任意文件。
- `FR-027` 每条记录至少包含 `spaceId`、`entityType`、`entityId`、`schemaVersion`、`revision`、`updatedAt`、由服务端认证确定的 `originClientId`、删除状态和 payload；服务端存储还必须具有不可由客户端绕过的所属账号关系。
- `FR-028` 每个客户端修改必须携带全局唯一 operation ID，以及它所基于的记录版本。
- `FR-029` 重试相同 operation ID 必须幂等，不得产生重复记录或重复版本。
- `FR-030` 服务端负责分配权威记录版本和有序空间游标，并从认证结果写入来源 `clientId`；客户端时钟和客户端自报来源不得决定全局顺序或来源身份。
- `FR-031` push 响应必须分别报告已接受、重复、冲突、校验拒绝、结构数量限制和存储不可用的操作。
- `FR-032` pull 请求必须返回游标之后的变更和新游标；分页期间发生写入时不得跳过变更。
- `FR-033` 在本地应用远端批次时，记录修改与游标更新必须原子提交；崩溃后只能重放或完整生效，不得出现游标已推进但记录缺失。
- `FR-034` 应用远端变更时不得把同一变更再次排入本地 outbox；客户端可以使用服务端返回的 `originClientId` 识别自己已确认的操作，但不得据此绕过 operation ID 幂等规则。
- `FR-035` 服务端必须保留足够的变更历史以覆盖支持的离线周期。游标过期时必须明确要求全量对账，不得返回不完整增量。
- `FR-036` 客户端与服务端必须协商 schema 版本。未知实体或版本必须隔离并提示升级，不得直接丢弃。
- `FR-037` 现有 LocalStorage 键和文件布局必须通过兼容适配器继续读取；同步迁移不得改写无关键或改变现有公开 schema。

### 8.5 实时、重连与离线行为

- `FR-038` 实时通道只负责通知“存在更新的游标”；业务数据仍通过已认证的增量同步完成，漏掉通知不能导致漏数据。
- `FR-039` 实时通道不得在 URL 中暴露客户端 Key，必须只订阅 Key 所属空间，并以认证出的 `clientId` 标记连接；在客户端 Key、空间或账号被禁用/吊销后，服务端必须关闭对应连接。
- `FR-040` 实时通道不可用时，在线客户端必须轮询，默认间隔不得超过 30 秒，并允许配置。
- `FR-041` 客户端必须在启动、系统唤醒、网络恢复和连接期间的周期检查时执行对账，即使没有收到实时通知。
- `FR-042` 本地写入不得等待网络；只有修改已进入持久 outbox 后，才能显示为“等待同步”。
- `FR-043` 重试必须使用有上限的指数退避与抖动，并遵守服务端重试提示。永久性校验、认证或结构数量限制错误不得无限重试；存储暂时不可用可按服务端提示重试。
- `FR-044` 重启应用或操作系统后，待发送操作、传输进度、最后游标和未解决冲突必须保留。
- `FR-045` 用户必须能立即暂停全部同步；暂停不得删除本地修改或待处理队列。
- `FR-046` 客户端必须显示最后成功同步时间、待处理记录/对象数量、最近错误、暂停/离线状态和未解决冲突数，且不得暴露秘密。

### 8.6 首次同步与重置

- `FR-047` 首次写入前，客户端必须获取服务端身份、远端条目/体积，以及已启用分类的本地条目/体积。
- `FR-048` 服务端空间为空时，默认首次同步动作为上传已启用的本地数据。
- `FR-049` 本地已启用分类为空时，默认首次同步动作为下载远端数据。
- `FR-050` 两端均有数据时，默认且推荐的动作必须是按稳定实体 ID 安全合并并保留冲突。
- `FR-051` “以本机为准”或“以服务端为准”必须是高级破坏性操作：显示影响条目/体积、先建立恢复点并要求明确确认，绝不能自动执行。
- `FR-052` 取消首次同步后，本地已有内容不得改变，设备也不得被标记为已完成同步。
- `FR-053` 全量重同步只能重建本地同步索引/游标，不得直接删除有效本地业务数据；任何删除必须经过墓碑和冲突规则。

### 8.7 冲突处理

- `FR-054` 基于当前版本的修改直接应用；基于旧版本的修改必须进入对应实体的合并策略。
- `FR-055` 不同 ID 的独立实体必须自动合并。
- `FR-056` 结构化记录中，仅一侧从共同基础版本修改过的字段必须自动合并。
- `FR-057` 同一有效字段被两侧改为不同值时，系统必须保留两个值及冲突记录，至少保存到墓碑/恢复保留期结束。
- `FR-058` 笔记标题或正文并发修改时，未成为当前值的版本必须保存为明确标记的冲突副本或等价可恢复版本，任何正文都不得静默丢弃。
- `FR-059` 待办与链接冲突必须保留确定性的当前值以及冲突字段，并提供解决操作；解决冲突会产生一个正常新版本。
- `FR-060` 可携带的非内容标量偏好可以按字段采用确定性的“服务端最后接受写入优先”。
- `FR-061` 排序必须使用稳定的单条排序数据，使移动一个条目不会覆盖整个集合。
- `FR-062` 冲突界面必须显示实体类型/标题、来源客户端、时间、差异字段，以及保留任一版本或手动合并的操作。
- `FR-063` 关闭冲突通知不得视为解决或删除冲突；未解决冲突必须始终可再次找到。

### 8.8 删除与恢复语义

- `FR-064` 删除同步记录时必须创建包含实体 ID、版本、删除时间和来源客户端的墓碑。
- `FR-065` 墓碑必须同步到所有已启用设备，默认保留 30 天，并允许配置更长时间。
- `FR-066` 基于墓碑之前版本的旧修改不得静默复活记录；记录保持删除，同时将旧修改保留为可恢复冲突数据。
- `FR-067` 在保留期内恢复记录时，必须生成新版本、取消活动删除状态并保留审计历史。
- `FR-068` 只有当不存在活动记录引用、墓碑/冲突保留期结束且备份保留不再需要时，才能回收对象。
- `FR-069` 保留期结束前永久清除数据必须是单独的用户/管理员操作，并明确提示不可恢复。

### 8.9 附件与大对象

- `FR-070` 二进制附件必须与 JSON 记录分开传输，并由加密摘要、字节数、MIME 类型和逻辑用途引用。
- `FR-071` 对象被标记完成或父记录显示为完整可用前，客户端和服务端都必须验证摘要与长度。
- `FR-072` 上传和下载必须支持分块续传、有限并发、取消和重试，已完成分块不得重复传输。
- `FR-073` 同一同步空间内相同字节可以复用一个对象，但跨空间或跨账号去重不得泄露其他空间是否拥有相同内容，也不得允许复用结果绕过对象授权。
- `FR-074` 未完成上传必须在可配置期限后过期，且不得显示为有效截图、剪贴板图片或笔记图片。
- `FR-075` 下载必须先写临时文件，校验成功后原子提交；失败传输不得覆盖已有有效本地文件。
- `FR-076` 删除记录不得立即销毁仍被共享或处于保留期的对象。
- `FR-077` MVP 不得设置账号或空间级的对象总字节、图片数量或单图大小业务配额。服务端仍必须声明技术协议边界，例如请求头/JSON 大小、单分块大小、并发数和超时；底层存储拒绝写入时必须返回明确可恢复错误。
- `FR-078` 同步服务不得在现有客户端生成能力之外再施加图片业务大小限制。桌面端现有笔记原图处理、PNG 转换和截图采集限制仍属于客户端输入规则，不视为服务端同步配额。
- `FR-079` 音频录音、完整录屏、未完成的 `.partial` 录屏和进行中的录制流均不属于 MVP 同步范围，不得进入同步 outbox。
- `FR-080` 附件延迟下载时，界面必须显示“仅远端/下载中/不可用”等明确状态，不得只呈现损坏路径。

### 8.10 实体专属规则

- `FR-081` 待办同步必须保留现有 `P0`-`P3` 存储含义、分类名称、完成状态、截止时间和稳定条目身份。
- `FR-082` 笔记、分类标签和引用的 `note-images/<noteId>/...` 对象必须作为一个逻辑依赖图同步，笔记不得永久引用缺失对象。
- `FR-083` 链接组和链接应尽量成为独立可识别实体，并同步标题、URL、描述、标签、收藏/已读状态、备注和时间。
- `FR-084` 剪贴板同步必须使用一个分类开关，同时覆盖规范化文字/URL/图片历史条目、收藏关系和图片对象；不得允许只同步文字或只同步图片。
- `FR-085` 多设备剪贴板保留规则必须确定。服务端不得因滚动历史上限而直接删除收藏条目，除非产品已明确规则并向用户提示。
- `FR-086` 截图库只能同步 `complete` 状态的截图元数据和对应 PNG 对象；录屏元数据、录屏文件和设备临时采集状态必须排除。
- `FR-087` 音频录音、转写文字和转写供应商凭据均不得进入 MVP 同步数据；后续音频同步必须另行定义媒体与转写依赖关系。
- `FR-088` 启用 AI 会话同步时，必须保留现有限额，并排除附件、图片、音频、API Key 和本地绝对路径，符合当前产品契约。
- `FR-089` 金融同步只能包含自选列表和选定的可携带显示偏好，必须排除供应商凭据、验证诊断和行情缓存。
- `FR-090` 应用设置必须使用允许列表。MVP 默认跨设备同步且仅同步主题、功能显隐和默认页；快捷键、开机启动、工作区路径、设备输入/来源及其他未明确列出的偏好必须保留本地。
- `FR-091` 刘海高度、首页布局等平台敏感设置必须保留在本机，或按平台命名空间同步，并在应用前按当前平台范围重新校验。
- `FR-092` MVP 不得同步本地音乐路径/文件、当前曲目、音量、发现缓存、启动器扩展代码/权限/存储、诊断和隐藏窗口状态。
- `FR-093` 同步 JSON payload 不得包含本地绝对路径。现有便携相对媒体引用必须在同步边界转换为稳定对象引用。

### 8.11 隐私、安全与滥用控制

- `FR-094` 设置界面必须说明：MVP 数据在传输和静态存储时受保护，但在未来增加端到端加密前，自托管服务端可以读取业务数据。
- `FR-095` 日志、指标、审计事件和错误报告必须脱敏授权值、笔记/剪贴板正文、含敏感查询值的 URL 和本地路径。
- `FR-096` 服务端必须对已认证请求执行请求头/JSON 大小、记录批次数、对象分块大小、速率、并发和连接限制。这些技术安全边界不得表现为对象总容量、图片数量或完整单图业务配额。
- `FR-097` 每种实体/schema 的 payload 必须按允许列表校验，不能写入任意 JSON 或文件。
- `FR-098` 对象存储路径不得信任客户端文件名，并必须防止路径穿越、符号链接和内容类型混淆攻击。
- `FR-099` 安全审计事件必须包括账号生命周期、账号认证、空间/客户端/客户端 Key 创建、Key 轮换或吊销、重复认证失败、分类清除、结构限制变更、备份策略变更和恢复操作。
- `FR-100` 审计事件必须记录账号作用域、来源客户端/操作者、动作、目标空间/对象标识、服务端时间和结果，但不得记录秘密或业务 payload。账号用户只能查询本账号审计，服务端管理员可按授权执行全局审计。

### 8.12 定时备份

- `FR-101` 服务端必须支持 S3 兼容备份目标，并允许管理员配置 endpoint、region、bucket、prefix、凭据、计划、时区、保留策略和加密配置；备份凭据必须进入服务端秘密存储。
- `FR-102` 生产 S3 兼容备份目标必须位于在线数据故障域之外。本地目录只允许用于开发或已挂载的独立备份介质；普通同目录/同磁盘副本必须显示警告，且不得宣称具备灾难恢复能力。
- `FR-103` 默认备份策略确定为保留 7 个每日、4 个每周和 12 个每月恢复点；管理员可以提高保留量，但不得配置低于该基线的生产策略。
- `FR-104` 每份备份必须代表账号、空间、记录、变更元数据、墓碑/冲突、对象引用和所需二进制对象的同一个逻辑时间点，并保留账号与空间归属关系。
- `FR-105` 每份备份必须包含 manifest：格式版本、服务端实例、账号与空间标识、各空间逻辑时间点/游标、创建时间、对象数量/字节和加密校验和。
- `FR-106` 备份产物必须静态加密；备份加密密钥必须与备份数据分开保存，且不得使用任何客户端 Key。
- `FR-107` 备份不得包含账号密码或客户端 Key 明文，只能包含恢复客户端身份、Key 校验状态和数据归属所需的最小校验值/元数据。
- `FR-108` 定时和手动备份必须报告排队、运行、成功或失败状态，以及起止时间、字节数、目标、manifest ID 和脱敏错误。
- `FR-109` 备份失败不得删除最后一个已知有效备份，并必须产生管理员可见告警或非零自动化退出状态。
- `FR-110` 只有新备份及其 manifest/校验和验证成功后，才能执行保留期清理。
- `FR-111` 服务端必须支持非破坏性验证，检查 manifest 可读性、校验和、必需对象和可解密性。
- `FR-112` 服务端必须支持恢复到隔离/暂存目标的 dry run，报告条目数、缺失/损坏对象、schema 兼容性和恢复时间点，不修改在线数据。
- `FR-113` 正式恢复必须明确确认；源数据仍可读时应先创建恢复前备份，并记录审计事件。
- `FR-114` 恢复后，服务端必须推进恢复 epoch 或等价身份，使客户端不能沿用旧游标，并要求安全全量对账。
- `FR-115` 恢复至少必须支持选择一个账号或一个同步空间恢复到指定备份点，且不改变其他账号或空间；单条记录选择性恢复可延后。
- `FR-134` 恢复账号或空间后，只能推进受影响空间的恢复 epoch/游标世代；未参与恢复的账号与空间必须继续同步且游标不变。
- `FR-116` 管理员必须能导出备份健康状态并自动执行定期恢复演练；推荐至少每季度一次。

### 8.13 导出、诊断与运维

- `FR-117` 已认证账号用户/管理员必须能导出其有权访问的单个同步空间，格式包含记录、来源客户端元数据、对象清单和校验和，但不包含账号密码或客户端 Key 明文。
- `FR-118` 导入必须在修改在线数据前完整验证 manifest，并使用与首次同步相同的合并/替换确认规则。
- `FR-119` 客户端诊断信息必须包含协议版本、服务端/空间身份前缀、游标年龄、队列数量、传输状态和脱敏错误码。
- `FR-120` 服务端健康检查必须区分进程存活、在线数据可用、对象存储可用和备份健康。
- `FR-121` 服务端升级前必须拒绝不支持的升级/降级组合，避免写入不兼容 schema。

### 8.14 Web 控制台与管理 CLI

- `FR-138` MVP 必须提供精简 Web 控制台。账号用户登录后可管理本账号的空间、客户端、客户端 Key、安装绑定、用量、审计和导出，不得进入服务端全局运维功能。
- `FR-139` Web 控制台必须提供登录、退出、修改密码、撤销其他会话和登录失败反馈；不得提供公开注册入口。
- `FR-140` 本地账号密码必须执行可配置的最小强度策略，首版默认至少 12 个字符；服务端必须使用适合密码的自适应单向哈希并支持未来参数升级。
- `FR-141` Web 会话必须使用安全的随机会话标识、有限有效期、空闲过期和服务端撤销；生产 Cookie 必须设置 `Secure`、`HttpOnly` 和合适的 `SameSite`，状态修改请求必须防止 CSRF。
- `FR-142` 登录与密码重置必须限速并记录脱敏审计；失败响应不得透露用户名是否存在。连续失败不得造成可被攻击者长期滥用的永久账号锁死。
- `FR-143` 创建客户端、轮换/重置客户端 Key、重置安装绑定、删除空间、吊销客户端和导出数据等高风险动作必须要求近期认证；客户端 Key 明文只能在客户端创建/轮换/重置成功页显示一次，离开后不可再次读取。
- `FR-144` Web 控制台创建或重命名空间时，必须以规范化名称检查账号内唯一性；名称冲突应返回明确但仅限本账号的信息。
- `FR-145` 服务端管理员 CLI 至少必须覆盖账号创建/列出/禁用/恢复/删除、密码重置、空间/客户端结构限制、用量查询、备份配置/运行/验证、暂存恢复和审计查询，并支持脚本化的稳定退出码；账号级客户端管理由 Web 控制台或受同等授权保护的管理 API 提供。
- `FR-146` 管理 CLI 输出秘密时必须遵守一次性显示和日志脱敏规则；默认列表和诊断输出不得包含密码、客户端 Key、备份凭据或业务正文。

## 9. 数据需求

### 9.1 同步矩阵

| 数据域 | 默认 | 元数据 | 二进制对象 | 冲突策略 | 说明 |
|---|---:|---:|---:|---|---|
| 待办和分类名称 | 开 | 是 | 否 | 字段合并 + 冲突保留 | 保持 `P0`-`P3` 兼容 |
| 笔记和分类标签 | 开 | 是 | 笔记 PNG | 正文冲突副本；分类字段合并 | 父实体与对象依赖 |
| 链接和分组 | 开 | 是 | MVP 否 | 字段合并 + 冲突保留 | 继续遵守公开 URL 规则 |
| 可携带应用偏好 | 开 | 是 | 否 | 按字段确定性选值 | 严格允许列表 |
| 剪贴板（文字、收藏和图片） | 关 | 是 | PNG | 追加/去重 + 墓碑 | 一个开关，历史仍按现有规则滚动保留 |
| 截图 | 关 | 是 | PNG | 元数据字段合并 | 敏感 |
| 音频录音 | MVP 不支持 | 否 | 否 | 不适用 | 图片同步稳定后再设计 |
| 屏幕录制 | MVP 不支持 | 否 | 否 | 不适用 | 大文件与恢复成本高 |
| 已保存 AI 会话 | 关 | 是 | 否 | 会话级冲突副本 | 遵守现有内容/体积上限 |
| 金融自选 | 可选 | 是 | 否 | 字段合并 | 不含凭据与行情缓存 |
| 自定义命令 | 关 | 是 | 否 | 冲突副本 | 可能含敏感文本 |
| 启动器收藏/别名 | 可选 | 是 | 否 | 字段合并 | usage 可留本机 |
| 天气位置 | 关 | 是 | 否 | 按字段选值 | 位置隐私 |
| 凭据/API Key | 永不 | 否 | 否 | 不适用 | 包括加密形式 |
| 本地路径/设备配置 | 永不 | 否 | 否 | 不适用 | 工作区、音乐、输入和快捷键 |
| 扩展和可执行代码 | 永不 | 否 | 否 | 不适用 | 信任边界 |
| 缓存/诊断/草稿 | 永不 | 否 | 否 | 不适用 | 派生或临时状态 |

### 9.2 记录不变量

- `DR-001` 实体 ID 必须稳定、全局低碰撞，并与本地文件路径无关。
- `DR-002` 服务端时间统一使用 UTC 时刻；用户区域/时区仅用于显示，待办截止时间保留原有时刻语义。
- `DR-003` 记录 payload 必须有明确 schema 版本，并限制字段、嵌套深度和总字节数。
- `DR-004` 笔记图片、剪贴板图片、截屏对象、分组/分类和收藏引用必须验证引用完整性。
- `DR-005` 记录必须以 digest/object ID 引用对象，不得引用文件系统路径。
- `DR-006` 在另行批准数据迁移前，客户端适配器必须保持现有 LocalStorage 和工作区 schema。
- `DR-007` 旧客户端不得静默改写未来版本的未知但有效字段。
- `DR-008` 服务端必须区分活动数据、墓碑、冲突、审计数据和备份产物的保留策略。

### 9.3 默认保留、结构限制与存储失败行为

- `DR-009` 墓碑和未解决冲突必须保留 30 天；生产配置不得缩短该窗口。
- `DR-010` 审计事件默认至少保留 90 天。
- `DR-011` 未完成对象上传默认在 24 小时内过期。
- `DR-012` MVP 不按对象总字节、图片数量或单图大小拒绝用户数据；底层存储空间不足或 S3 写入失败时，必须保留本地内容和重试元数据，且不得静默淘汰服务端已有内容。
- `DR-013` 资源错误响应必须说明是账号空间数、空间客户端数、协议技术边界还是底层存储失败，并给出当前数量/限制或可重试状态。
- `DR-014` 服务端清理必须确定且可审计；不得为了接纳新内容而静默淘汰任意用户内容。

### 9.4 账号与空间归属不变量

- `DR-015` 每个空间、客户端、记录、变更、冲突、墓碑、对象引用、游标和审计事件必须能追溯到且只追溯到一个所有者账号和一个空间；账号级审计、结构限制或用量记录除外。
- `DR-016` 客户端提供的 `accountId`、`spaceId` 或 `originClientId` 不得作为授权或来源依据；客户端 Key 必须在服务端解析为唯一账号、空间和客户端作用域。
- `DR-017` 即使底层对象存储执行全局物理去重，每个对象授权和引用计数仍必须按空间隔离，不能通过摘要探测其他账号或空间的数据。
- `DR-018` 账号内空间名称在 Unicode 规范化、去除首尾空白和产品定义的大小写规则后必须唯一；空间身份使用不可变 ID，重命名空间不得改变客户端绑定、游标或对象权限。
- `DR-019` 账号和空间对象总字节、图片数量仍必须可统计和展示，但仅用于容量观察与备份规划，不构成 MVP 业务配额。
- `DR-020` 每个活动客户端 Key 必须对应唯一客户端记录；客户端显示名称可以修改，但 `clientId`、历史 `originClientId` 和所属空间不得随重命名改变。
- `DR-021` `installationId` 用于防止一个客户端 Key 被多个安装误用，不得由 MAC 地址、磁盘序列号或其他硬件指纹派生，也不得作为账号或空间授权的替代品。

## 10. 非功能需求

- `NFR-001 可用性：` 服务端离线或不可达时，本地创建、修改和删除仍可使用。
- `NFR-002 在线延迟：` 正常网络和服务负载下，95% 的纯元数据修改必须在 3 秒内出现在另一台已连接设备。
- `NFR-003 持久性：` 客户端一旦显示本地操作已排队，应用重启不得丢失；服务端一旦确认，正常进程重启不得丢失。
- `NFR-004 幂等性：` 重放任何已确认操作或已完成对象分块，不得产生重复用户数据。
- `NFR-005 传输安全：` 生产流量必须使用 TLS 1.2 或更高版本，并执行正常证书和主机名验证。
- `NFR-006 秘密处理：` 客户端 Key 除操作系统安全存储外不得以明文静态保存，也不得进入日志、URL 或备份。
- `NFR-007 租户隔离：` 账号认证不得访问其他账号；客户端 Key 不得访问其他客户端身份或未授权空间。任何请求都不得读取、推断或修改未授权空间的记录、对象存在性、缓存、实时事件、用量、审计、导出或备份恢复结果。
- `NFR-008 资源边界：` 所有列表、批次、payload、对象分块、队列和并发传输都必须有文档化的有限上限。
- `NFR-009 背压：` 大媒体传输不得阻塞元数据同步，也不得使 Electron renderer 无响应。
- `NFR-010 兼容性：` 客户端与服务端必须声明协议兼容范围，并在不兼容写入前明确失败。
- `NFR-011 可观测性：` 认证、校验、冲突、结构限制、存储、传输和备份失败必须使用稳定的脱敏错误码。
- `NFR-012 无障碍：` 状态和冲突控件必须支持键盘操作、具有文本标签，且不能只依赖颜色表达。
- `NFR-013 备份 RPO：` 使用默认计划时，文档承诺的最坏恢复点不得超过 24 小时；实现持续日志/对象版本捕获的部署可声明更低 RPO。
- `NFR-014 备份 RTO：` 对参考容量空间，文档化恢复流程应以 4 小时内完成为目标，不含外部下载瓶颈。
- `NFR-015 完整性：` 恢复后的备份必须先通过 manifest、校验和、schema 和引用完整性验证，再激活。
- `NFR-016 隐私默认：` 后续新增的敏感分类在完成分类和确认前必须默认关闭。
- `NFR-017 多租户故障隔离：` 一个账号或空间达到结构数量限制、产生异常请求、遇到存储/备份失败或执行恢复时，不得阻塞或改变其他账号/空间的正常同步。
- `NFR-018 授权覆盖：` 所有以账号、空间、客户端、记录、对象或备份 ID 为输入的端点都必须执行对象级授权测试。随机且不可猜测的 ID 不能替代授权检查。
- `NFR-019 Web 安全：` Web 控制台必须满足会话固定防护、CSRF 防护、输出编码、内容安全策略和安全响应头要求；依赖账号密码的敏感响应不得被共享缓存。
- `NFR-020 来源可信性：` 服务端保存的每个 `originClientId` 必须来自成功认证的客户端 Key 映射，不能来自客户端可修改字段；客户端重命名、Key 轮换或安装绑定重置不得改写历史来源。

## 11. 边界场景

- `EC-001` 设备离线时间超过服务端变更流保留期，需要全量对账且不能丢弃其待发送修改。
- `EC-002` 两台设备分别修改和删除同一笔记。
- `EC-003` 同一个客户端 Key 被误配到两个应用安装，或操作系统镜像克隆了本地绑定状态；服务端必须仍将其识别为同一个 `clientId` 并暴露异常并发使用。
- `EC-004` 客户端 Key 轮换时该客户端正在上传图片；同空间其他客户端不得受影响。
- `EC-005` 相同服务端 URL 指向了实例 ID 不同的新装服务。
- `EC-006` 对象上传完成但元数据提交失败，或元数据已存在但对象校验失败。
- `EC-007` 客户端在应用记录与保存游标之间的任一时点崩溃。
- `EC-008` 传输进行中用户关闭对应分类。
- `EC-009` 首次同步期间底层对象存储耗尽或拒绝写入；客户端必须保留本地对象和续传状态。
- `EC-010` 旧元数据包含 Windows/macOS 绝对路径或缺失附件。
- `EC-011` 两台设备分别导入了没有稳定 ID 的同一条旧记录。
- `EC-012` 设备时钟与服务端严重偏差。
- `EC-013` 备份目标已满、不可用，或写入返回成功但后续校验和不匹配。
- `EC-014` 备份 schema 版本低于当前服务端支持范围。
- `EC-015` 服务端恢复到旧时间点，但客户端仍有更新的待发送修改。
- `EC-016` 收藏剪贴板条目即将被 100 条滚动历史规则淘汰。
- `EC-017` 应用退出时存在未完成的录屏。
- `EC-018` 当前客户端离线期间，其 Key 被账号用户吊销。
- `EC-019` 同一账号创建或重命名为规范化后重复的空间名称时，操作必须拒绝；客户端仍必须显示稳定空间标识，避免相似名称误绑定。
- `EC-020` 本地工作区原先绑定客户端 A，用户输入属于空间 B 或客户端 B 的 Key；客户端 A 的 outbox 不得以客户端 B 的来源身份发送。
- `EC-021` 账号被禁用时，其客户端离线积累修改；恢复账号后必须按原空间执行正常冲突对账。
- `EC-022` 账号删除或空间删除与定时备份同时发生，备份必须落在明确一致的前/后状态。
- `EC-023` 两个账号上传相同摘要对象，任何一方都不能据此确认另一方拥有该对象。
- `EC-024` 一个空间恢复到旧时间点，同账号其他空间继续写入；恢复不得回滚其他空间。
- `EC-025` 单个客户端 Key 泄露后被轮换；同空间其他客户端 Key 和同步连接必须保持有效，审计能够定位泄露来源客户端。

## 12. 成功指标

- `SM-001` 并发、删除、重试和崩溃注入验收中不存在已知静默数据丢失。
- `SM-002` 正常负载下，至少 95% 在线元数据变更达到 3 秒跨设备可见目标。
- `SM-003` 100% 重复操作测试只产生一个逻辑结果。
- `SM-004` 100% 抽样备份通过自动 manifest/校验和验证。
- `SM-005` 每季度暂存恢复成功，且不存在缺失的引用对象。
- `SM-006` 同步记录、普通日志和导出中不存在客户端 Key、第三方 API Key、密钥库 payload 或本地绝对路径；每条服务端接受的写入均能追溯到认证出的 `clientId`。
- `SM-007` 用户无需打开开发者工具即可判断当前绑定空间、同步健康状态和错误所属分类。
- `SM-008` 多账号/多空间授权测试中，所有跨边界访问、对象探测、实时订阅、导出和恢复请求均被拒绝，且响应不泄露目标存在性。

## 13. 验收条件

- `AC-001` 给定空服务端空间和含笔记/待办/链接的设备，首次同步会上传已启用分类；第二台空设备可重建等价内容。
- `AC-002` 给定两台在线设备，正常负载下 100 次纯元数据编辑中至少 95 次在 3 秒内出现在另一设备。
- `AC-003` 离线修改在应用重启后仍存在，并在重连后按因果顺序同步。
- `AC-004` 相同 mutation operation 重放 100 次，只产生一个逻辑版本/结果。
- `AC-005` 同一笔记并发编辑时保留两份正文，并持续显示未解决冲突，直到用户处理。
- `AC-006` 一台设备删除记录后，离线设备的旧修改不能静默复活记录，且旧修改可恢复。
- `AC-007` 保留期内恢复墓碑记录会生成新版本并出现在所有已启用设备。
- `AC-008` 即使实时通知丢失，轮询/对账仍能补齐变更。
- `AC-009` 在记录应用与游标持久化周围每个事务边界注入崩溃，只会安全重放或完整应用，不会跳过变更。
- `AC-010` 中断的附件传输可续传，最终 digest 与源文件一致；损坏字节会被拒绝。
- `AC-011` 所有必需对象验证前，笔记/截屏不得显示为完整可用。
- `AC-012` 未启用剪贴板开关前，文字、URL、收藏和图片都不会进入服务端；启用后四者一起同步，界面不存在独立图片开关。截图和 AI 会话仍使用各自独立开关；音频录音和录屏在任何 MVP 配置下都不会进入同步数据。
- `AC-013` 关闭分类会停止传输，但不会删除本地或远端记录，除非用户另行确认删除。
- `AC-014` 生产配置拒绝明文 HTTP，显式启用的回环开发端点除外。
- `AC-015` 数据包、请求和日志检查未发现 URL、查询参数、普通日志或遥测中的客户端 Key。
- `AC-016` 服务端存储和备份检查未发现客户端 Key 明文。
- `AC-017` 吊销客户端 A 的 Key 后，其 API 和实时访问被阻止，同空间客户端 B/C 继续同步。
- `AC-018` 轮换客户端 A 的 Key 遵守所选立即/重叠策略，旧 Key 在期限后失败，其他客户端 Key 不变。
- `AC-019` 同步 payload 检查未发现密钥库数据、第三方 API Key 或本地绝对路径。
- `AC-020` 配置 URL 返回不同服务端实例 ID 时，客户端在 push 前停止，并要求用户确认。
- `AC-021` 游标过期后，客户端执行安全全量对账，同时保留待发送 outbox。
- `AC-022` 旧客户端遇到不支持 schema 时会隔离并提示升级，不会改写或删除数据。
- `AC-023` 底层对象存储耗尽或暂时不可用时，客户端保留本地内容和续传状态、指出存储错误，且不会持续高频请求服务端。
- `AC-024` 未完成 `.partial` 采集不会作为完整媒体上传。
- `AC-025` 定时备份包含有效 manifest 和其逻辑时间点引用的全部对象。
- `AC-026` 备份失败时保留上一个已知有效备份，并产生可见失败状态或非零自动化结果。
- `AC-027` 未验证或失败的新备份之后不会运行保留期清理。
- `AC-028` 恢复 dry run 能检测故意删除/损坏的对象，且不修改在线数据。
- `AC-029` 已知有效备份的暂存恢复能重建记录、墓碑、冲突和对象，并通过引用完整性检查。
- `AC-030` 恢复后，连接中的客户端不能沿用旧游标，并会重新对账，不会静默覆盖恢复状态。
- `AC-031` 后续实现完成时，既有 Electron 测试和存储兼容测试必须继续通过。
- `AC-032` 一个服务实例创建两个账号，每个账号创建至少两个空间后，账号只能列出和管理自己的空间。
- `AC-033` 同一空间预建客户端 A 和 B 并分别生成不同 Key 后，两者共享该空间变更；同账号另一空间及其他账号空间不会收到记录、对象或实时通知。
- `AC-034` 使用客户端 A 的 Key，把请求中的 `spaceId`、`originClientId`、记录 ID、对象摘要或游标改为客户端 B/空间 B 时，请求被拒绝或来源被服务端强制记为 A，且响应不透露未授权目标是否存在。
- `AC-035` 客户端 Key 无法登录账号管理接口、创建/列出客户端、列出同账号其他空间或读取账号总用量。
- `AC-036` 同一应用安装依次绑定客户端 A 与客户端 B 时，两套 Key、`clientId`、游标、outbox、冲突和附件映射保持隔离；客户端 A 的待发送操作不会以客户端 B 的来源发送。
- `AC-037` 禁用一个账号会终止其所有空间的管理和同步访问，但其他账号继续同步；重新启用后通过正常对账恢复。
- `AC-038` 停用一个空间只停止该空间，同账号其他空间继续同步。
- `AC-039` 恢复一个指定空间后，仅该空间客户端需要重建游标；同账号其他空间和其他账号的游标、记录与对象不变。
- `AC-040` 两个账号上传相同字节对象时，任何跨账号存在性检查、下载或时间差观察都不能形成可用的数据探测通道。
- `AC-041` 一个账号创建第 11 个活动空间时被拒绝；一个空间创建第 11 个活动客户端时被拒绝。该限制不影响其他账号或空间中的现有同步。
- `AC-042` 未登录访问 Web 控制台受保护页面会被拒绝，且页面中不存在公开注册入口。
- `AC-043` 服务端管理员通过 CLI 创建账号后，该账号可用本地用户名/密码登录；错误用户名与错误密码返回不可区分的失败响应。
- `AC-044` 同一账号创建或重命名为规范化后重复的空间名称会被拒绝，其他账号可以使用相同空间名称。
- `AC-045` 客户端 Key 在创建、轮换或安装绑定重置结果中只显示一次，刷新或再次打开页面不能取回明文；普通日志和浏览器持久存储中不存在该明文。
- `AC-046` 修改密码或执行“撤销其他会话”后，旧 Web 会话在下一次受保护请求时失效；桌面客户端 Key 不受影响，除非另行吊销。
- `AC-047` 缺少或伪造 CSRF 证明的 Web 状态修改请求被拒绝；跨站页面无法创建空间/客户端、轮换客户端 Key 或删除数据。
- `AC-048` 管理 CLI 可以脚本化完成账号生命周期、结构限制、用量查询和备份/恢复操作，成功与失败使用稳定退出码，输出不包含禁止的秘密。
- `AC-049` 客户端 A 和 B 分别写入一条记录后，服务端和冲突/审计界面显示两个不同的、与各自 Key 绑定的 `originClientId`。
- `AC-050` 客户端 A 在 payload 中伪造客户端 B 的 `originClientId` 时，服务端不会保存伪造值；记录来源仍为 A，且产生适当的校验或安全审计结果。
- `AC-051` 同一空间创建三个客户端时，服务端生成三个不同 Key；任一 Key 的吊销、轮换或过期均不改变其他两个 Key 的有效性。
- `AC-052` 同一客户端 Key 首次绑定安装 A 后，再从安装 B 使用会被拒绝并产生安全审计；安装 B 的写入不会被记为该客户端来源。
- `AC-053` 重置客户端安装绑定会立即撤销旧 Key、生成只显示一次的新 Key，并允许新安装绑定；同空间其他客户端持续同步。
- `AC-054` 重命名客户端或轮换其 Key 后，新旧记录仍显示同一个不可变 `originClientId`，历史来源不被重写。
- `AC-055` 一个空间创建 10 个客户端时，所有活动客户端 Key 均不同并分别解析为唯一 `clientId`；第 11 个活动客户端创建请求被拒绝。
- `AC-056` 一个账号可以创建 10 个活动空间且正常同步；第 11 个活动空间创建请求被拒绝，并返回当前数量与上限。
- `AC-057` 上传对象时，服务端不因账号/空间对象总字节、图片数量或完整单图大小业务配额拒绝；超过请求或分块技术边界时返回协议错误并允许按协议重新分块。
- `AC-058` 墓碑和未解决冲突在第 30 天结束前保持可恢复；默认备份清单包含 7 个每日、4 个每周和 12 个每月恢复点。
- `AC-059` 新设备同步设置后只接收主题、功能显隐和默认页；快捷键、开机启动、工作区路径及其他偏好保持本地。
- `AC-060` 本地账号登录、修改密码、管理员重置和会话撤销流程均不显示 MFA 设置、恢复码或二次验证码步骤。

## 14. 已确认的产品决策

| 主题 | 已确认 MVP 决策 | 需求影响 |
|---|---|---|
| 服务端信任 | 服务端可读，使用 TLS + 服务端静态加密 | E2EE 延后，不把客户端 Key 当作加密恢复密钥 |
| 账号模型 | 一个服务实例多账号；每账号多空间；每空间多客户端 | 账号是管理边界，空间是数据同步与隔离边界 |
| 账号创建 | 仅服务端管理员通过管理 CLI 创建 | MVP 不开放匿名自助注册 |
| 账号认证 | 服务端本地用户名/密码 | 桌面同步客户端不接收账号密码，OIDC 延后 |
| 空间命名 | 同一账号内规范化后唯一 | 空间仍使用不可变 ID，重命名不改变绑定 |
| 管理入口 | 账号用户使用精简 Web 控制台；服务端管理员使用管理 CLI | Web 管空间/客户端/客户端 Key/用量/审计，CLI 管账号/结构限制/备份恢复 |
| 客户端身份 | 空间内先创建具名客户端，每个客户端由服务端生成独立 Key，并在首次连接时绑定随机安装 ID | 禁止同空间多个客户端共享 Key；Key 唯一映射到账号、空间和 `clientId`，不同安装 ID 复用会被拒绝 |
| 来源归属 | 服务端从客户端 Key 认证结果写入 `originClientId` | 不信任 payload 自报来源；单客户端吊销/轮换不影响其他客户端 |
| 媒体范围 | 只同步笔记图片、剪贴板图片和截图 | 音频录音与屏幕录制明确排除出 MVP |
| 敏感默认值 | 剪贴板/截图/AI/位置/命令默认关闭 | 首次上传前展示条目数、体积和敏感等级 |
| 首次同步 | 默认安全合并；允许建立恢复点并二次确认后的高级整端覆盖 | 不提供无提示的“最新覆盖” |
| 空间与客户端上限 | 每账号最多 10 个活动空间；每空间最多 10 个活动客户端 | 达到上限后拒绝新增，但不影响既有同步 |
| 对象业务配额 | 对象总字节、图片数量和完整单图大小暂不设上限 | 保留请求、分块、并发和底层存储的技术安全边界 |
| 剪贴板开关 | 一个开关同时控制文字、URL、收藏和图片 | 不提供文字/图片拆分开关 |
| 默认设置同步 | 仅主题、功能显隐和默认页 | 其他设置暂时保持本地 |
| 账号 MFA | MVP 不支持 | 只提供高强度密码、会话撤销和管理员重置 |
| 删除保留 | 确认为 30 天 | 旧客户端不能越过墓碑复活数据 |
| 实时方式 | 通知通道 + 游标对账 + 30 秒降级轮询 | 通知丢失仍可通过对账补齐 |
| 对象传输 | 可续传、内容寻址对象 | 适用于笔记图、剪贴板图和截图 |
| 生产备份 | S3 兼容存储为主 | 本地目录仅用于开发或独立挂载备份介质 |
| 备份保留 | 确认为 7 个每日、4 个每周、12 个每月恢复点 | 生产策略不得低于该基线 |

## 15. Requirement Gate

Sync MVP v1 当前产品决策已全部确认，可以进入接口地图和技术设计阶段。后续若增加 MFA、对象业务配额、录音/录屏同步或更多可携带设置，必须作为显式版本变更重新评审。
