## 建议先做什么

把 AI 用在“把当前材料变成可用内容”上：用户选定文字、笔记或录音转写，执行一个具体动作，在预览中编辑结果，然后复制、保存笔记或加入待办。

首版优先打通两条路径：

1. **文字 → 待办草稿 → 确认加入四个责任领域**。适合随手输入、粘贴需求、整理笔记中的行动项。
2. **录音转写 → 摘要 / 行动项 → 分别保存笔记与待办**。复用现有录制与百炼 ASR，保存音频后再整理。

“摘要、精简、翻译、提取待办”共用一个结果预览组件和一个主进程请求服务。笔记、录音提供就地入口，启动器提供跨页面入口。保持常驻面板短时使用的特点，结果有明确去向。

第二阶段再做带来源的工作区问答、长录音分段整理和本机模型；跨应用选区读取、回填及屏幕理解单独评估。

## 目标用户与假设

目标用户为同时使用待办、笔记、链接、录音的个人知识工作者，包括学习、内容创作与开发场景。暂按以下假设规划，后续试用可以修正：

- 中文为主，偶尔处理中英混合内容；可自行配置现有 LLM/ASR 服务。
- 希望减少从文字整理到待办、笔记之间的重复复制。
- 更看重 10–60 秒内完成一个小操作，以及结果可编辑、可撤销。
- 不需要账号、多人协作、云同步或独立聊天应用。
- 现阶段没有使用频率、模型质量及付费预算的真实数据，优先级为产品判断，不是用户研究结论。

## 首版完成后的典型体验

用户输入：“明晚九点前发产品演示视频，周日交课程报告，购买电池的事以后再说。”选择“提取待办”。预览显示前两项对应的原文、责任领域和明确日期；“以后再说”不会被模型武断地补成某个截止时间，用户可以补日期或取消勾选。点击“加入 2 项待办”后，仍进入原有 2 × 2 待办布局，今天/本周/以后由 `deadline` 自动派生。

用户录完一段想法，音频先保存。点击“整理录音”，生成摘要及行动项。可先保存摘要为笔记，再单独确认待办。服务失败时原音频与转写仍在，可重新整理。

## 决策与待验证事项

| 事项 | 当前建议 | 后续验证 |
| --- | --- | --- |
| 第一条开发路径 | 文字提取待办，共用结果预览 | 5 位目标用户完成预设任务，评估修改量与耗时 |
| 自动调用模型 | 新安装默认关闭内容自动整理；现有用户由迁移提示主动恢复开关 | 旧设置迁移与文案测试 |
| 模型选择 | 实时转写与内容整理使用独立槽位；内容服务由厂商注册表和协议 adapter 驱动，每个厂商可保存最多 12 个模型并指定默认项 | 对各厂商和具体模型执行真实连接、结构化输出与中文语料评测，不凭型号更新排序 |
| 长内容 | 首版限制单次范围且明确提示；后续分段覆盖全部材料 | 摘要遗漏率与总调用成本 |
| 本机推理 | 第二阶段可选 Ollama，先适配，不内置下载模型 | 双平台内存、首响应与终端地址策略 |
| 项目排期 | MVP 约 18–28 人日，另留 20% 风险余量 | 基础阶段结束后按真实接口、质量和平台结果重估 |

开发计划中的核心闭环已经落地；任务编号与验收条件仍作为追踪基线。真实模型质量、用户试用、macOS 实机和安装包检查完成前，不把本方案标记为完整发布验收通过。
