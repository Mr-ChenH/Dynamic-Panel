# AI 工作流需求

> 状态：MVP 需求与验收基线。核心闭环已实施；逐项证据、偏差及未完成验收见 [07-implementation-report.md](07-implementation-report.md)，当前产品行为以根 README 为准。

## 1. 产品目标

让用户在当前面板内将文字和录音转写整理为可复制、可保存、可执行的内容。首版覆盖文字动作、待办提取和录音整理，共用一套结果预览及本地保存能力。

用户应清楚四件事：正在处理哪段材料、会发送给哪个服务、结果还没保存、点击操作后保存到哪里。

## 2. 用户场景

| 场景 | 用户动作 | 预期结果 |
| --- | --- | --- |
| 随手记下多件事 | 在启动器执行“从文字提取待办”，输入或粘贴文字 | 可编辑的待办候选，带领域、截止时间和原文依据 |
| 整理笔记 | 笔记页选中文字或整篇，选择“摘要/精简/翻译/提取待办” | 在原页面预览；复制、另存，或对合法选区应用精简/翻译 |
| 录音后的整理 | 停止录音并保存后，点击“整理录音” | 摘要、原文支持的关键决定与行动项；分别保存笔记、加入待办 |
| AI 结果不正确 | 编辑候选、取消勾选、重新生成或关闭 | 原内容不变；已应用结果可在本次会话内撤销 |
| 没有网络或 Key | 使用普通待办、笔记、录音、搜索 | 本地能力继续可用，AI 入口提示配置或重试 |

## 3. MVP 功能要求

| ID | 要求 | 验收要点 |
| --- | --- | --- |
| FR-001 | 启动器提供“摘要文字”“精简文字”“翻译文字”“从文字提取待办”内置入口 | 搜索命令名仅匹配；选择命令打开输入区，点击“生成”才请求模型 |
| FR-002 | 输入来源只允许手动输入/粘贴、用户指定笔记或笔记选区、指定录音转写 | 展示来源名称、范围、字符量和处理服务；可展开检查实际文字 |
| FR-003 | 共用结果预览 | 显示生成中、停止、编辑、复制、另存笔记及适用的写入动作 |
| FR-004 | 从文字提取待办 | 每次最多 20 个候选，每项有可定位的原文；不把假设、已取消或已完成事项作为默认选中任务 |
| FR-005 | 责任领域兼容 | 展示当前用户分类名；写入仅接受 P0–P3；不将其解释为优先级 |
| FR-006 | 截止时间审阅 | 有歧义、过去时间或缺少时间时明确标记；未解决候选不能加入正式待办 |
| FR-007 | 可编辑、选择性加入、去重提示 | 用户可改标题/领域/日期、取消候选；显示当前列表中的相似项，不自动删除或合并已有任务 |
| FR-008 | 批量写入与撤销 | 单次原子更新原待办键，失败无部分添加；同一批次重复点击只应用一次；撤销不覆盖后续手工改动 |
| FR-009 | 笔记内容动作 | 摘要/精简/翻译/提取待办；复制或另存；选区精简/翻译在原内容未变化时可应用并撤销 |
| FR-010 | 录音整理 | 对已保存转写生成摘要、明确决定及任务候选；分别保存笔记或待办，不自动串联写两个数据键 |
| FR-011 | 原文依据与状态保护 | 引用必须来自本次快照；原对象删除、编辑、工作区切换后结果标为过期，不自动覆盖新内容 |
| FR-012 | 自动命名可控 | 链接/笔记/录音自动命名分别设置；手动命名动作可重试且保护用户改名；新安装默认关闭这些 LLM 自动动作 |
| FR-013 | 服务配置与验证 | “设置 → AI 与转写”区分实时转写、内容整理、自动动作；保留 Key/Base URL/模型，增加显式连接与结构化能力检测 |
| FR-014 | 取消、超时和失败恢复 | 用户停止、关闭结果视图、渲染销毁或工作区切换时取消请求；旧响应不得覆盖当前视图；失败保留输入 |
| FR-015 | 首版长内容限制 | 单次原文最多 12,000 UTF-16 code units，界面称“字符”；超限要求选择范围，不静默只发前半段 |
| FR-016 | 最小调用与本机诊断 | 普通搜索、打开笔记、普通录音保存不引入新 LLM 调用；默认不保存提示词、正文和回复诊断日志 |

### 3.1 日期规则

- 提交请求时固定 `referenceTime` 与本机 IANA 时区；服务执行和预览共用这份时间基准。
- 当前文本中的“明天/周日”以请求时的日期为基准；历史录音按录制开始时间解释，相应基准显示在预览中。录音记录只有时间戳，无法可靠恢复旅行前的原始时区时，提示用户核对日期。
- 笔记里的相对日期不假定为创建日期；默认按本次请求日期解释并展示，可改参考日期后重新生成。
- 只有截止表述才能直接提议 deadline。“周四开始做”“有空再说”不能直接变成截止日期。
- 只有日期没有时刻时，可以提议该日 23:30，必须显示“默认时刻”；已过点或明显过去的时间要求用户重新选择。
- 未提及截止时间时保留空候选字段，提供“今天/本周/以后默认时间”作为用户主动选择的按钮，计算复用 `defaultTodoDeadlineForScope`。不得默认为紧急。
- 正式写入仍必须有合法且经用户确认的截止时间，不新增 `scheduledAt`、无日期持久收件箱或第二套时间分类。
- “今天/本周/以后/全部”仅根据保存后的 `deadline` 派生；P0–P3 只表达责任领域。

### 3.2 提取与生成的区分

“提取待办”只收集输入中出现的行动；每项有引用。若用户请求“帮我规划一门课程”，MVP 提示输入已有事项或使用普通文字记录，不伪造“原文提取”。“拆解任务/建议下一步”是后续单独动作，必须标为建议。

摘要中的不确定内容保留不确定性。没有明确决定时显示“未发现明确决定”；没有任务时允许返回空列表，不以补齐数量为目标。

### 3.3 自动行为的迁移

- 旧 API Key、区域、业务空间、Base URL 与模型保留，禁止迁移时清空或重新加密明文回传。
- 现有版本没有内容自动动作偏好；首次升级增加一次说明，内容自动动作先关闭，用户可主动恢复。已有记录标题与分类不批量更改。
- 云端实时转写单独控制：对原已配置并使用转写的用户保留原录音转写体验；新配置页说明开启录音时会向该 ASR 服务发送音频。
- 自动命名开启时，只处理未命名且未被用户修改的对象；源版本改变则丢弃响应。正文超过处理上限时跳过并提供手动选择范围入口。
- 自动链接整理只发送 URL 与网页标题；默认网页标题、图标抓取及本地规则分类继续运行。

## 4. 后续需求

| ID | 能力 | 进入条件 |

| NEXT-001 | 长录音/长笔记分段整理 | MVP 质量达标，有明显超限使用需求；完整覆盖原文并保留分段引用 |
| NEXT-002 | 工作区问答与来源引用 | 受控本地检索、来源白名单与失效检测实现；回答不得冒充全库穷尽搜索 |
| NEXT-003 | 本机 Ollama | 独立 loopback 策略、无 Key 状态、能力检测与资源测试完成 |
| NEXT-004 | 自定义 AI 文本命令 | 内置动作稳定；命令模板不包含 Shell/文件执行能力，不复用旧常用指令为可执行代码 |
| NEXT-005 | 任务拆解与“下一步建议” | 与原文提取明显区分；先以独立待办草稿呈现，不改根结构 |
| NEXT-006 | AI 完成事件转笔记/跟进 | 用户主动选择事件；只使用收到的标题/项目等数据，不读取外部 Agent 会话文件 |
| NEXT-007 | 跨应用选区、回填或屏幕上下文 | 双平台原生能力研究与焦点/权限人工验收，单独立项 |
| NEXT-008 | 网页全文摘要 | 新建受控正文提取链路，保留公网/重定向限制，明确登录页不可抓取 |

## 5. 非目标

首版不提供通用聊天历史、向量库、全盘语义搜索、日历自动排程、自动完成或删除任务、网页代理、MCP 工具调用、无人值守 Shell、常驻截图/麦克风观察、系统音频捕获、音频文件导入转写、说话人识别、精确音频时间戳或模型自动下载。

AI 不读取密钥库、密码、API 配置明文、整个剪贴板历史、扩展私有数据。用户手动粘贴的文本可能含敏感内容，界面应显示将提交的内容；不能宣称能自动识别并阻止全部敏感数据。

## 6. 非功能要求

| ID | 要求 | 验收方式 |
| --- | --- | --- |
| NFR-001 | 无 AI 时可用 | 无 Key、离线、服务异常时普通搜索/待办/笔记/录音保存正常 |
| NFR-002 | 响应及时 | 点击生成后 100ms 内显示忙状态（本机目标）；不阻塞键盘、导航与录音结束 |
| NFR-003 | 请求有界 | 单次原文 12,000 字符，IPC 请求 64 KiB；响应体 256 KiB、有效结果文本 64 KiB、最多 20 个任务，超限明确失败 |
| NFR-004 | 等待可控 | 交互请求默认 30s 截止，可调 10–60s；没有流式内容也显示进度状态；停止立即更新 UI 并 abort |
| NFR-005 | 安全边界 | sandbox/contextIsolation 保持；渲染层通过 preload；模型输出无法指定 IPC、Shell、路径或动态加载代码 |
| NFR-006 | 私密配置 | Key 由 safeStorage/环境变量提供；不进入 LocalStorage、工作区导出或诊断 |
| NFR-007 | 兼容与持久化 | 原 P0–P3、笔记 archive、录音结构保留；捕获 quota 和工作区保存失败；不伪报完全保存 |
| NFR-008 | 可撤销与幂等 | 同一会话的 proposal ID 只能写一次；撤销按对象/字段比对，冲突时保留用户新内容 |
| NFR-009 | 双平台布局 | 展开内容区复用 1240 × 540 上限与自适应安全距，最窄测试宽度 640 DIP、内容高 400 DIP；更小可用区进入单列滚动且主操作可达 |
| NFR-010 | 窗口与焦点 | 复用现有 launcher/expanded 模式，不增加原生窗口；不破坏 Windows shape、折叠屏幕跟随和退出焦点策略 |
| NFR-011 | 可访问性 | 键盘完成主流程；IME Enter 不误提交；可见 focus、可读对比度、减少动态效果、结果状态 aria-live |
| NFR-012 | 数据最小化 | 只发送指定文本与必要的分类名/时间基准；不附带隐藏模块、音频文件或未选来源 |

上述限制是拟实现默认值，不是服务商能力说明；阶段 M0 可根据评测调整，调整须同步交互、契约与测试。

## 7. 数据要求

- 草稿、原文快照、引用和撤销记录仅保存在当前应用会话内存；重新载入或切换工作区后消失，UI 明示“尚未保存”。
- 已确认待办写入 `notch-todo-data`；正式对象只含现有领域字段。
- 摘要等另存为普通 Markdown 笔记，写入 `notch-note-archive-v1`；来源标题、生成时间和引用摘录可作为笔记可见正文，不伪装成既有双向关系。
- 不把原笔记图片路径复制为新笔记附件；MVP 输出文本，源笔记附件保持原目录。
- 录音的音频与完整转写保持原存储，生成摘要不会替换转写。
- 同一结果的“保存笔记”与“加入待办”是两次独立本地写入，各自记录成功和撤销，不承诺跨键原子事务。
