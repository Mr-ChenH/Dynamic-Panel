# AI 功能验证与验收计划

> 本文件记录完整验收方法，**不是通过报告**。应用行为自动化已经执行；真实模型质量、用户试用和安装包验证仍未执行，结果见 [07-implementation-report.md](07-implementation-report.md)。

## 1. 三种验证分别报告

1. **应用行为**：用固定假响应验证界面、请求、状态与存储，不依赖模型随机输出。
2. **内容质量**：用脱敏人工语料和真实模型验证提取、摘要与日期理解；记录模型、提示版本和参数。
3. **平台表现**：真实 Electron、Windows/macOS、窗口焦点、多屏及安装包验证。

一种通过不能替代另一种。不得用供应商 HTTP 200 当质量达标，不得用缺失性能事件的当前时间填充值假装测到了焦点/首帧。

## 3. AI 输出质量评测

### 3.1 样本集

建议先建立 60 条固定、脱敏样本。可由开发者编写，至少一位非提示词作者复核期望值；输出变更不能倒过来随意改金标准以制造通过。

| 类型 | 数量 | 重点 |
| --- | ---: | --- |
| 明确任务与领域 | 10 | 1–5 条行动、中英术语、自定义领域名 |
| 日期/时间 | 12 | 明天、下周、开始与截止区别、历史录音、23:30、周末和 DST |
| 否定/取消/不确定 | 8 | “先别做”“已经完成”“也许以后”“如果批准再做” |
| 录音转写整理 | 12 | 口语重复、ASR 错字、决定变更、没有行动项、长文关键点在末尾 |
| 笔记摘要/精简/翻译 | 10 | 保留事实、数字、约束、中英混合、Markdown 图片邻近内容 |
| 对抗与异常输入 | 8 | 来源内提示注入、越权请求、伪造引文、超限和不完整文本 |

样本包含：ID、原文、动作、referenceTime、时区、当前分类名、应提取/应忽略项、允许的日期解释、关键事实。不要以模型自评作为唯一标准。

### 3.2 评测方法

- 基线为当前用户配置模型；候选最多一个作对比，使用相同输入/参数/promptVersion。
- 首轮每条一次；对易错日期和否定样本重复 3 次，单独报告不稳定率，不能只挑最好结果。
- 人工对齐行动项，记录漏提、误提、事实改变、引用不支持；对边界不确定项用“需要用户确认”作为合法结果。
- 每个测试报告记录服务/模型实际名称、日期、参数、输入输出 token（如有）、请求失败数和总费用（若服务提供或已知定价），不用代码默认型号冒充已测试型号。
- 使用假响应的自动测试只验证处理逻辑；真实服务评测是显式的可选命令，不接入默认 `npm test`。

### 3.3 建议门槛

这是立项目标，尚未取得实测值。

| 指标 | 定义 | 建议 MVP 门槛 |
| --- | --- | --- |
| 结构有效率 | 非网络失败请求中可通过本地 schema 的结果比例 | ≥98%；不足时不能开放批量直接应用 |
| 行动项精确率 | 输出行动项中确有原文承诺/行动依据的比例 | ≥95% |
| 行动项召回率 | 金标准明确行动项中被正确提取的比例 | ≥90%，同时报告遗漏原因 |
| 明确日期准确率 | 具有唯一正确解释的日期样本正确率 | ≥95% |
| 不确定日期处理 | 模糊/缺失日期没有被伪装成已确认日期 | 边界集 100% 被标注或要求修正 |
| 引用完整性 | 引用 ID/原文片段在所选输入中可验证 | 应用层校验 100%；语义支持仍人工复核 |
| 摘要事实保持 | 人名/数字/否定/决定未被改变 | 高风险错误为 0；其他关键点覆盖 ≥90% |
| 本地响应 | 点击生成到忙状态，测试环境中记录 | p95 ≤100ms |
| 模型等待 | ≤2000 汉字文字动作端到端 | 暂定 p95 ≤15s，未达标则优化模型/范围或重估产品目标 |
| 结果写入 | 重复/部分失败/撤销错误 | 故障用例为 0；不允许降低此标准 |

报告分母、样本量、失败请求与模型版本。60 条样本只能作为上线前小基准，不代表所有真实内容准确率。

### 3.4 初步用户试用

建议邀请 5 位目标用户，每人完成 3 个固定任务：从文字创建待办、笔记精简、录音转写整理。对照手工流程记录耗时、修改次数和是否找到保存入口。

- 目标：至少 4/5 用户无需指导完成生成与保存，理解“尚未保存”。
- 目标：多数用户在至少两项任务中比手工流程更快；不给未经测量的节省百分比。
- 若用户频繁关闭生成结果而不采纳，先检查来源/结果质量和操作命名，不直接增加更多模型按钮。
- 内容不上传为产品分析；本机统计只记动作和计数，试用记录由参与者主动提供。

## 4. 双平台验证

| 环境 | 必查 |
| --- | --- |
| Windows 11 x64 | IME、快捷键冲突、DPI、固定画布/shape、透明点击穿透、已有应用窗口切换 |
| Windows 10 x64 | Electron 支持环境下相同行为、系统密钥加密、文本控件与窗口焦点 |
| macOS 13+ arm64 | 全局快捷键、辅助功能既有焦点行为、刘海/菜单栏、麦克风生命周期、safeStorage |
| 物理多屏 | 折叠跟随、展开固定、LLM 返回不跳屏、不同 DPI/菜单栏高度 |
| 两平台安装包 | 新 ai 模块是否打包，preload/renderer 资源、网络/加密、首次升级迁移 |

自动化缺少真实 focus/paint 样本时明确记“未采集”，查明原因或标记不可测，不替换为一个有限数值绕过断言。

## 5. 执行顺序和发布条件

1. M0 建立基线与纯函数/provider 测试。
2. M1 跑一条生产 Electron 文字 → 待办路径及失败/撤销场景。
3. M2 完成笔记、录音和现有桌面全套 `npm test` 回归。
4. 在有可用服务与调用范围时执行脱敏真实模型质量评测，记录成本和未测项。
5. 双平台源码实机验证；有打包授权后执行安装包验证。
6. 联动版本号、package-lock、CHANGELOG、根 README 与实际下载入口；两平台发布条件满足后按仓库流程处理。

未通过数据写入、密钥边界、取消过期或麦克风释放检查时，不能因内容质量较好而通过发布验收。单个平台未执行就明确留下未执行项。
