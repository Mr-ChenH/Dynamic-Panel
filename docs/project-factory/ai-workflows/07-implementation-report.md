## 1. 已交付范围

### 统一请求底座

- `ai/schema.js` 集中校验动作、请求大小、12000 UTF-16 code units 输入上限、结构化响应、最多 20 个待办和原文依据。
- `ai/prompts.js` 对摘要、精简、翻译、待办提取、录音整理和兼容自动命名使用版本化提示词。
- `ai/providers.js` 将厂商注册表与协议分离：内容服务覆盖 DeepSeek、OpenAI、阿里云百炼、Kimi、智谱 GLM、SiliconFlow、Gemini、OpenRouter、Azure OpenAI、Anthropic 和自定义 OpenAI-compatible；每项声明端点、鉴权、推荐模型、结构化输出与流结束能力。
- `ai/service.js` 通过 `openai-chat` 和 `anthropic-messages` adapter 生成请求并解析普通响应与 SSE；二者共用 30 秒总超时、DNS 阶段起即可取消、固定公网解析、供应商错误映射、并发边界和 256 KiB 响应上限。OpenAI SSE 依厂商能力要求 `[DONE]` 或正常 `finish_reason: stop`；Anthropic 要求 `message_stop`，并拒绝截断、过滤和非正常 `stop_reason`。畸形帧和不完整响应均不能作为成功结果保存。
- `main.js` 只接受白名单结构，通过 `ai:run`、`ai:cancel`、`ai:test-provider` 暴露能力；渲染进程销毁、工作区切换或 AI 配置保存时取消活动与排队请求。远程 HTTPS 请求固定使用已经过公网检查的 DNS 地址，避免请求时二次解析绕过。
- 旧 `smart:organize-material` 和启用后的链接智能命名继续可用，但都改由统一服务执行；笔记、录音和链接自动命名均携带稳定 source ID 与内容 revision，再按来源合并并进入最多 10 项的有界队列。交互请求保持优先；队列等待最多 30 秒，并绑定入队时的工作区/配置代次，过期或上下文变化后不再发送。取消中的底层请求在真正结算前继续占用并发槽位。

### 用户工作流

- 启动器提供“从文字提取待办 / 摘要文字 / 精简文字 / 翻译文字”四个显式命令。
- 待办页提供“从文字添加”，生成后逐条编辑标题、责任领域和截止时间，并可复用现有规则选择“今天 / 本周 / 以后”，再一次性写入原 `notch-todo-data`。
- 缺少、无效、已过去的截止时间不能保存；待办必须保留能在原文中定位的摘录。
- 批量保存具有当前会话幂等保护和冲突安全撤销：用户保存后继续修改的待办不会被撤销误删。
- 笔记详情提供“整理笔记”和“生成标题”；选区存在时仅发送选区，精简和翻译结果可以替换选区并撤销，选区包含 Markdown 图片时不提供直接替换。选区位置校验保留未裁剪原文，首尾空白不会造成错误 revision；生成标题先预览和编辑，再显式采用。
- 录音详情提供“整理录音”和“生成名称”；链接条目提供智能名称/分类动作。名称和分类都先预览，采用前校验来源与旧名称，并支持冲突安全撤销；链接分类复用现有分组。
- 录音整理只发送已保存的转写文字，音频文件不进入模型请求。摘要可另存为普通 Markdown 笔记，行动项仍需补齐并确认后加入待办。
- AI 工作台支持停止请求、关闭或切换工作区时取消、来源变化检查、复制结果和明确错误状态；生成期间锁定输入、动作和流式结果，完整结束后才开放编辑。新会话会重置请求控件，旧响应不能污染重开的工作台；保存、采用和撤销使用会话级互斥，异步返回后再次校验会话。服务主机、来源范围、参考时间及时区均在请求前显示。普通搜索与正则搜索不会触发模型。
- AI 写入会区分 LocalStorage 成功与工作区快照同步失败；同步失败时保留已写入的本机数据并明确提示，由既有周期同步继续重试，不会重复追加。

### 配置与隐私

- “设置 → AI 与转写”直接使用左侧服务/厂商列表和右侧配置区，不再打开二级弹窗；“实时转写”和“内容整理”仍是两个固定服务槽位。实时转写继续使用阿里云百炼 Qwen3-ASR；内容整理由厂商注册表驱动表单。每个内容厂商可保存最多 12 个自由输入的模型并指定默认模型，同时保留独立端点、超时、加密凭据和逐模型验证状态。左栏显示厂商模型数量、默认模型以及已验证、失败、待保存和待移除状态，右侧保存区保持可达；录音配置入口会直接定位实时转写。
- 配置升级为 `schemaVersion: 3`，包含 `services.transcription`、按厂商划分的 `services.content.profiles`、`automations` 和逐服务/模型 `verification`。旧平铺和版本 2 单模型字段会幂等迁移且继续镜像当前默认配置以兼容旧代码；旧模型成为对应厂商的首个默认模型，端点、密文、自动开关与环境变量行为不会因默认值更新而改变。
- 两个服务分别验证和移除配置。内容验证先检查文本响应，再检查结构化输出；状态区分未配置、待验证、已验证、验证失败、结构化输出不兼容和 Key 需重新输入。验证结果绑定厂商、端点、具体模型和实际凭据，切换默认模型不会把另一模型的状态误用过来，配置在请求期间变化时不会污染新状态。
- 三个自动调用开关默认关闭。配置文件通过同目录临时文件和原子重命名写入；已保存的厂商切换回来时复用该厂商自己的加密 Key，首次配置或凭据失效时才要求输入。移除内容配置只删除当前厂商，其他厂商不受影响；更换或移除转写配置会终止仍使用旧配置的会话。
- API Key 继续由主进程 `safeStorage` 或环境变量解析，不返回渲染层、不进入 LocalStorage 和工作区导出，已保存 Key 不在表单中回显。
- 新请求只发送用户当前明确选择的文字、分类显示名、当前时间和时区；模型输出不能指定 IPC、Shell、文件路径、LocalStorage key 或永久对象 ID。
