## 需优先修复的现有代码问题

### A-001：扩展超时不保证结束

位置：`launcher/extension-host.js` 的 `finish()`。

finish 清除超时后调用一次 `child.kill()`，Promise 等待 close。macOS/Unix 子进程可处理并忽略 SIGTERM，此时没有 SIGKILL 升级或最终上限。扩展派生子进程继承管道也可能延迟 close。当前超时测试使用普通 setInterval 进程，未覆盖拒绝终止的进程。此结论为代码审查，不是当前 Windows 环境下的 macOS 复现。

### A-002：卸载和并发没有真正等待进程回收

位置：`launcher/service.js` 的 `cancel/change/uninstall/query`。

cancel 只调用 abort，未返回/等待 host 退出 Promise；uninstall 随即删 registry 和目录。Windows 可能在进程仍占用目录时删除失败，registry 却已去掉该扩展。`dynamic.slice(0, 3)` 只限制一批查询，不能保证跨请求、执行阶段的全局并发上限。registry 写入固定 `registry.tmp`，多个 toggle/remove/install 没有统一串行队列。

### A-003：搜索期间远端选择丢失

位置：`renderer/launcher.js` 的 `search()` → `render()`。

用户已选中一个应用/扩展后继续输入，search 清空 remote，render 发现 selectedId 不在列表内并清除；异步结果返回时只会选首项，即使原选项仍匹配。与 FR-014 不符。慢扩展还与应用结果共用完整响应 Promise，导致应用结果等待扩展超时才返回。

### A-004：失败导航计入使用统计，错误可能不可见

位置：`renderer/launcher.js` 的 `run()`。

navigate 未实际执行时已经保存 usage，之后先 close 再调用 NotchPanel.navigate。若目标功能被禁用/目标无效，失败仍提升统计，并把错误写到已隐藏的 launcher status。需要先验证目标并完成动作，再记成功和关闭；失败保留可见上下文。

### A-005：结果定位不完整

位置：`renderer/app.js` 的 `NotchPanel.navigate()` 与 `completedTodoDisclosureHtml()`；`renderer/launcher.js` 的链接映射。

已完成待办默认不生成实体行，navigate 没有展开对应完成区，因此 scrollIntoView 无目标。笔记 select 返回 false 未检查。链接结果未保留对象 ID，“打开链接页面”只切 Tab，无法定位目标。

### A-006：关闭、管理和异步查询存在状态竞争

位置：`renderer/launcher.js` 的 `open/close/showManager/search`。

打开过程中 Escape/失焦直接被 transition guard 忽略，未记录待关闭意图。管理页仍保留可输入搜索框，其 input handler 继续发送查询，可能在管理上下文执行扩展或更改隐藏列表。管理页异步操作没有统一 busy/error/取消机制，切换和卸载失败的返回值未展示。

## 原计划状态与建议顺序

14 个 TASK 应保留“部分完成/待验收”，逐项补齐其验收条件，而不是全部关闭。

1. **稳定性优先**：修复 A-001/A-002/A-006；建立可等待的取消、强制回收和串行 registry 事务。
2. **主路径正确性**：修复 A-003/A-004/A-005，补真实输入/执行/导航/失焦回归。
3. **需求缺项**：绝对路径打开、来源分组、完整动作模型、集中收藏/别名管理、入口/风险展示和运行诊断。
4. **规格决策**：可信进程权限边界、本机扩展安装策略和超时默认值与原 PRD 的差异需明确统一，不以实现现状反向宣布原需求完成。
5. **验收补齐**：重启/迁移、安全边界、真实 Electron 扩展运行、性能基准和双平台自动化；硬件人工检查单独记录。

在线商店、云同步、全盘索引、计算器/网页搜索、zip、签名等原本明确后置或可选的项目，不计入本轮必需功能欠账。
